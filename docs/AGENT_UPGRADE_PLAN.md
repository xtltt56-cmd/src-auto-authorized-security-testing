## 1. 升级目标与完成定义

把现有“固定检测流程 + 可选模型分诊”扩展为能根据真实观察结果选择下一项许可动作的安全测试 Agent。操作方式保持为：人工录入目标和确认授权，人工启动任务，系统在批准的范围与动作集合内自动执行，人工负责候选的最终确认与补天提交。

升级后的核心循环为：读取目标与既有证据 → 模型选择一个许可动作 → 程序校验权限、参数和额度 → 现有工具执行 → 保存脱敏观察结果 → 模型决定下一动作、结束或请求人工处理。

“算 Agent”的最低验收标准：

- 两个不同观察结果能触发不同的后续动作，动作由模型选择并通过程序校验；不能把固定分支包装成模型自主规划。
- 至少一个本地场景完成两轮工具反馈循环，并能说明每一步使用的证据和简短执行理由。
- 工具真实失败、证据不足或模型失效时，状态与报告如实反映问题。
- 所有动作均可关联到同一任务、授权摘要、动作版本、观察记录与执行结果。
- Agent 无权扩大授权、修改安全开关、操作明文密钥或自动提交报告。

初版采用一个执行循环，提供“候选复核”和“API 权限检查”两种任务模式。模式共用模型接口、动作目录、状态库和执行器；不先引入多个相互通信的 Agent。

`SafeToolAdapter` 当前对传入目标做入口校验，但不能据此证明第三方工具内部所有网络请求均受 `ScopeGuard` 控制。因此它不能直接接受模型生成的任意命令，也不能直接作为真实目标 Agent 的通用执行器。

## 3. 技术选择与成熟方案复用

1. 沿用 Python 3.8 兼容要求、项目 SQLite、React/Vite Dashboard、既有模型与扫描器适配器。小规模有限动作循环优先使用现有代码和标准库 `dataclasses`、`json`、`sqlite3`、线程取消机制。
2. 新增项目特有的动作目录和校验规则；不自行实现认证、密钥加密、HTTP 协议或扫描引擎。
3. ZAP 的自动化计划优先使用官方 Automation Framework，并固定经过审阅的环境和任务配置；先接被动检查与已有请求分析。Schemathesis 继续沿用现有 GET/examples 配置。工具路径、版本和可用性均重新核对。
4. Nuclei 等工具仅允许经过审阅、固定版本与摘要的模板配置；模型不能自行下载模板或添加执行参数。无法控制工具出口、无法满足本地测试要求的工具保持不可用于该任务。
5. LangGraph 可作为后续复杂状态流程的候选，但当前 PyPI 版本要求 Python >=3.10，与本项目声明的 3.8 兼容约定不一致。初版不因此改造整个运行时；只有原型证明状态编排明显超出已有实现时，再单独评估锁定依赖、运行时升级及迁移成本。
6. 不要求用户同时购买多个模型或商业扫描器。Agent 使用本地模型或用户已有且本次明确启用的模型 API。

参考依据：

- [Anthropic：Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)：根据工具结果进行循环决策，设置结束条件，先采用简单可组合实现。
- [LangGraph 官方概览](https://docs.langchain.com/oss/python/langgraph/overview)：可混合确定性步骤与 Agent 步骤，支持持久化和人工介入。
- [LangGraph PyPI 运行时要求](https://pypi.org/project/langgraph/)：本次查证要求 Python >=3.10；实施时须复核选定版本。
- [ZAP 官方 Automation Framework](https://www.zaproxy.org/docs/automate/automation-framework/)：使用环境、任务、任务验证和真实退出状态组织既有扫描能力。

## 4. 权限、模型与执行方式

### 4.1 权限归属

授权确认、范围检查、请求校验、STOP、密钥解密、工具启动和最终裁决都由程序或人工控制。模型只能提出动作建议。

每个任务固定绑定目标 ID、确认范围摘要、时间窗、动作目录版本、测试会话引用、模型配置版本和本次 AI 授权。范围或参数发生变化后，旧审批不能自动沿用。

### 4.2 三种运行模式

| 模式 | 行为 | 云端请求 |
| --- | --- | --- |
| 标准检测 | 现有确定性检测流程；模型不可用时仍可明确选择它 | 不因 Agent 设置产生远程请求 |
| 本地 Agent | 调用已验证可用的本地模型选择许可动作 | 0 |
| 云端 Agent | 启动时允许云端 AI，并在任务摘要中明确选择模型、查看发送内容类型与调用上限后点击开始 | 仅属于该次任务的许可调用 |

现有启动选择“否”的服务器硬门必须覆盖所有 Agent API；保存密钥、打开页面、刷新任务和读取报告均不得触发云端模型请求。开始一项云端 Agent 任务是明确的人工动作，不能仅凭以前保存的密钥推断授权。

模型失败不得自动切换到云端、其他提供商或更贵模型。本地模式失败可暂停，或由用户选择标准检测；界面须如实标识规则工作流与模型循环。

### 4.3 初版允许动作

| 动作 ID（拟定） | 输入 | 执行边界 |
| --- | --- | --- |
| `read_observation` | 同任务观察 ID | 读取脱敏记录，不联网 |
| `inspect_headers` | 固定靶场/已批准入口 ID | 单次有限 GET/HEAD；校验跳转 |
| `discover_surface` | 目标 ID、有限发现配置 ID | 同源、限定数量；禁止遍历所有子域 |
| `inspect_api_schema` | 已批准规格 ID | 本地文件或固定回环规格入口；拒绝未经许可的远程引用 |
| `compare_objects` | 合成响应记录 ID | 离线比较；不返回原始敏感正文 |
| `compare_object_authorization` | 已批准权限用例 ID | 固定合成对象、所有者/同级/匿名会话；只读请求 |
| `schema_smoke` | 固定本地规格与检查配置 ID | 沿用 GET/examples、单 worker 和现有请求限制 |
| `review_candidate` | 候选及观察 ID | 提取缺失证据；不得将建议文字当命令执行 |
| `request_human_review` | 证据引用、缺失条件 | 暂停或进入人工队列 |
| `finish` | 结束原因 | 保存结果、生成草稿 |

M4 可增加经过验证的 ZAP 被动分析配置；初版目录不包含任意 shell、任意 HTTP 请求、账号注册、密码尝试、任意脚本、任意 SQL、自动模板下载或主动利用。

## 5. 决策契约、观察与任务状态

### 5.1 模型返回结构

模型返回严格、有限的 JSON。目标和会话由服务器绑定，不能由模型覆盖。例如：

```json
{
  "action": "compare_object_authorization",
  "case_id": "approved-order-case-01",
  "input_evidence_ids": ["obs-003"],
  "reason": "现有观察缺少同级测试账号的权限对照"
}
```

不同动作拥有单独的参数规则。未知字段、未知动作、其他任务的证据 ID、未批准对象 ID、原始命令或 URL 均拒绝。无效输出最多允许一次不涉及工具执行的格式修复；再次失败则暂停。

原生 Tool Calling 是可选传输格式；没有原生工具调用能力的模型也可使用受限 JSON 决策。两个入口都必须经过同一个校验器。

### 5.2 观察记录

保存观察 ID、动作与用例版本、授权摘要、请求方法与脱敏目标、状态码、字段摘要/指纹、耗时、错误类型、依赖版本和证据引用。会话仅保存引用，Cookie、Token、密钥、个人信息与批量正文不进入模型上下文或公开日志。

页面、脚本、API 规格、响应和导入文件只作为不可信数据；其中出现的“忽略范围”“上传密钥”“执行命令”等文字不能改变工具目录、系统规则或权限。

### 5.3 任务工作记忆

使用同任务的结构化上下文：已批准入口、已发现端点、合成角色/对象关系、已执行动作、未满足的验证条件和证据索引。上下文按需裁剪并保留证据引用，不引入跨客户、跨目标的默认共享记忆库。

### 5.4 状态与恢复

建议内部状态：`CREATED → PREFLIGHT → DECIDING → VALIDATING_ACTION → EXECUTING → OBSERVING`；观察后可返回 `DECIDING`，或进入 `AWAITING_HUMAN`、`COMPLETED`、`BLOCKED`、`CANCELLED`、`FAILED`、`INTERRUPTED`。

- 当前 Dashboard 类型须显式兼容新增状态；旧任务仍可读取。
- 每次动作先记录待执行状态，再记录真实结果，并关联唯一动作 ID。
- 相同任务、范围、动作、参数、会话版本与证据版本形成幂等键；仅在同任务、有效时限内复用已经完整记录的只读结果。
- 重启不自动恢复网络或云端调用；显示“已中断”，由用户选择继续。
- 继续前重新核对范围、时间窗、模型会话授权、会话有效性、工具版本与 STOP。
- 无法确定上一步是否完成时标记为未知，不当作成功；只读动作经检查后可重新执行。
- SQLite 采用向后兼容的新增表/字段，记录迁移版本。重要迁移前备份数据库，不复制整个 Docker 数据盘。

### 5.5 初版循环限制（实施前 M0 核实）

本地试验建议：单任务最多 8 次工具动作，单候选最多 4 次跟进，格式修复最多 1 次，普通失败最多 1 次受限重试；任务最多 12 次模型调用。并发默认 1。

普通 HTTP 动作建议 10 秒超时；长工具使用独立超时并受任务总时长约束。单任务建议 15 分钟；实际请求总量按动作配额累计，所有跳转、重试和内部请求计入。

建议单次模型输入不超过 6,000 Token、输出不超过 800 Token；根据实际模型能力及本地推理速度调整并记录。模型等待超过超时应显示超时，不继续伪造进度。

遵循用户此前“不强制设置金额上限”的偏好：金额上限为可选项。必须保留步数、请求数、时长与 Token 限制；显示实际用量，价格未知时显示“金额未知”，不伪报免费或成本为 0。

## 6. 分阶段实施与验收

### M0：建立新基线与验证资料

工作：

1. 记录实际 Git 提交、Python/Node/Docker 运行路径、端口、工具路径和版本、五靶场配置、现有测试命令及数据库版本。
2. 核对靶场就绪和固定回环绑定；Docker 不可用时先恢复依赖，只测试可用场景，不把旧结果作为新通过。
3. 建立版本化的合成本地权限规格、正例、修复版负例及正常对照；划分检测信息与评估答案，Agent 不得读取 Ground Truth。
4. 用现有标准流程跑一轮基线，记录遗漏、误报、请求量、耗时、资源与依赖失败情况。
5. 建立 `agent_enabled=false` 功能开关和实施分支；后续分阶段提交。重要数据迁移采用适量备份。

交付：基线记录、用例清单、动作目录草稿、依赖核验、恢复步骤。项目生成内容全部在项目目录。

通过条件：基线来源可追溯；当前无法测试的部分明确列出；旧 Dashboard 和标准检测继续可用。未达到此条件不接真实模型工具循环。

### M1：接通单 Agent 核心循环和模型接口

工作：

1. 新增严格决策契约、动作目录、独立执行校验器、最小观察结构和有限循环。
2. 复用 `ScopeGuard`、资源守卫、STOP、模型设置与 DPAPI；范围、权限和凭据由服务器持有。
3. 将本地模型与现有云端提供商转换成相同决策接口；保留现有单候选审阅入口。
4. 模型名称使用当前用户保存且通过能力核验的配置；支持手动刷新服务商目录。无法获取目录时显示需填写/确认，不能擅自换模型。
5. 本阶段仅接离线记录和固定回环 `inspect_headers` 等低风险动作；先用受控假响应验证契约，再使用真实本地模型。

交付：真实两轮反馈闭环、失败/暂停行为、模型能力说明和本地动作日志。

通过条件：输入变化能改变动作选择；未知动作和越权参数执行次数为 0；未启用远程 AI 时远程调用数为 0；异常输出不触发工具。只有假响应验证通过时，不得宣称真实 Agent 模型联调完成。

### M2：候选复核 Agent

工作：

1. 从当前数据库选择候选，提取已有观察、证据引用及缺失条件。
2. 模型选择安全跟进动作，执行器校验后运行，结果返回同一循环。
3. 区分安全配置建议、API 契约异常、可疑授权边界与已充分验证的问题；缺少响应头不自动提升为高危漏洞。
4. 对授权异常检查对象归属、公开性、账号角色和期望权限；仅响应等价不能直接证明 IDOR。
5. 超过上限、缺少测试账号、证据互相矛盾或请求失败时进入人工复核。
6. 复用 `adjudication.py`，模型只能提出候选结论。`TRUE_POSITIVE` 和 `submission_ready` 的最终设置由人工裁决接口控制；本地自动评分使用隔离的测试答案记录。

交付：每个候选的证据缺口、跟进动作、对照结果、复现草稿和人工队列。

通过条件：对本地已知正/负例有可核验的跟进记录；模型单次高置信度不能直接生成已确认状态；证据不足如实保留未验证。

### M3：API 与业务权限 Agent

工作：

1. 复用现有 OpenAPI 检查、会话库、响应对象对比和授权矩阵。
2. 读取已批准的规格和权限说明，选择对象、所有者、同级账号、匿名等测试组合；只使用操作人已准备的测试账号和对象。
3. 拟定用例必须引用批准的角色、会话和对象 ID；执行参数由程序渲染，模型不能枚举任意对象或增加未经批准的请求方法。
4. 本地 `business-api` 增加易理解的脆弱配置、正确权限配置和公开对象对照；重置仅作用于合成数据。
5. VAmPI 用于有限的规格发现与只读契约场景；Juice Shop、DVWA、WebGoat 用于流程和证据链验证，不能假定全部教学挑战均可由此覆盖。
6. 首版覆盖对象级权限与只读角色差异。支付、退款、库存并发、状态跳转和跨租户写入不包含在首版承诺中，后续按独立合成用例扩展。

交付：规格与测试矩阵、逐账号对照证据、已知权限正/负例成绩和适用范围。

通过条件：测试规格与评估答案分离；正确权限和公开对象对照不被误判为已确认越权；五靶场均显示实际检测覆盖与未覆盖项目。

### M4：已有工具的受控编排

工作：

1. 模型依据观察选择“本地有限发现”“被动检查”“规格检查”等配置 ID，程序映射到固定工具参数。
2. 首批复用现有本地发现、HTTP 探测、Schemathesis 和 ZAP 被动分析；工具是否可执行须以当前依赖核验为准。
3. 固定工具版本、插件与配置摘要；执行器处理真实退出码、警告、超时、无效工件和取消。
4. 校验工具内部访问、重定向、插件网络行为和隐藏请求；采用工具官方范围配置、可验证的请求入口或受控代理。不支持强制出口检查的工具不授予真实目标自动执行能力。
5. 不把“二进制存在”当成“可用于 Agent”；不把任务正常退出当成“发现漏洞”。

交付：工具能力表、范围与取消核验、真实规范化观察、与标准流程的请求量和耗时对照。

通过条件：同源范围外请求均被实际拦截；工具异常准确显示；能在明确场景减少重复或无关检查。收益未证实时该工具保持标准工作流入口。

### M5：Dashboard 可视化、状态持久化与人工裁决

工作：

1. 在现有靶场页面增加“标准检测 / Agent 检测”选择；旧入口保持清晰，新模式先默认关闭。
2. 在候选详情增加“Agent 辅助复核”；本次模型、许可动作、外部数据发送类型和上限在任务摘要中展示。
3. 复用内嵌 AI 设置页；显示当前已保存配置、能力核验状态和未保存修改，不弹出多层密钥窗口。
4. 在 `TaskDetailPage`、`EventTimeline`、`FindingDetail` 中显示当前动作、简短理由、输入证据引用、真实执行结果、用量、人工待办和报告入口。无需显示模型内部思维链。
5. 动态循环显示已完成动作数、用量与当前状态；尚不知道总工作量时不显示虚假的完成百分比。
6. 加入停止、暂停、人工继续、模型失败切换至标准模式等明确操作。停止任务和关闭浏览器须有不同语义。
7. 持久化授权版本、动作、观察、用量和人工决策；重启显示中断，人工继续时重新预检。
8. 后端复用现有令牌、来源和项目身份检查。新增接口只接受目标/候选/配置 ID；不接受任意命令和路径。

拟定接口：创建 Agent 任务、读取任务与动作事件、停止任务、在新预检后继续、记录人工裁决。最终 URL 与 DTO 命名沿用项目现有约定。

交付：简体中文可操作界面、真实后端事件、报告关联、完整脱敏导出和恢复演示。

通过条件：在 1280×720、1366×768、1920×1080 以及 125%/150%/200% 缩放下检查布局；按钮能完成真实交互；中文无替换字符；服务断连、重启、取消和报告截断均准确显示。

### M6：授权目标能力的独立准入

本阶段是可选扩展。实现入口与用模拟、本地服务器验证权限不代表取得了任何真实网站测试授权。

工作：

1. 将目标草稿、人工确认范围、自动化允许项、测试时间窗和测试账号绑定为版本化的任务审批记录。
2. 每次请求核对域名、端口、路径、方法、跳转、解析地址和时间窗；校验失败在发送前停止。模型不能添加范围。
3. 默认仅允许经核验的低频只读动作；有状态操作需要单独合成场景和动作准入，首版保持禁用。
4. 用户审阅任务摘要并显式开始后，范围内许可的中间步骤可以自动运行；范围变更、账号条件变化和不许可动作应暂停。
5. 对出站防护不能强制生效的第三方扫描器，只保留离线分析、结果导入或人工工具入口。

交付：明确的授权目标任务入口、逐请求范围记录和越界模拟测试结果。

通过条件：先通过所有本地/模拟门控用例。真实目标实测必须具备该目标的具体授权，成果仅限该目标与时间窗；没有实测时标识“功能已实现，真实项目效果尚未验证”。

2. 生成本轮执行报告和操作手册，统一 README、KNOWN_ISSUES、发布清单和界面状态；所有分数标明数据集版本、模型配置、实际执行方式和时间。

5. 按当次发布授权提交代码、推送仓库、生成对应 Release 和校验摘要；源码版本和最新下载包版本一致后才宣布发布完成。

通过条件：干净安装可完成已声明的本地流程；现有客户数据不被更新包覆盖；未通过的可选能力不出现在完成承诺中。

## 7. 验收数据与发布门槛

### 7.1 冻结的三组用例

- 检测组：至少 20 个合成权限场景，10 个已知缺陷、10 个修复版/公开对象/正常对照。必须保存权限期望，不能仅依赖 HTTP 状态。
- 门控组：至少 20 个场景，覆盖未确认范围、范围过期、跨域跳转、DNS/解析地址变化、远程规格引用、未知动作、恶意网页指令、证据串用、云端禁用和敏感信息外传尝试。
- 生命周期组：至少 8 个场景，覆盖取消、超时、模型失效、工具缺失、服务重启、未知完成状态、人工继续和配置变更。

具体用例在 M0 冻结版本，检测信息不包含评估答案。回归失败不能通过删用例、放宽范围或把未执行标为通过解决。

### 7.2 必须达到的门槛

1. 在已执行门控用例中，未经许可的请求、未授权远程模型调用、密钥泄露和自动提交均为 0。
2. 执行动作与实际结果可追溯率 100%；停止或中断后的状态不残留为持续运行。
3. 已有标准检测、报告查看与 AI 设置的相关回归通过。
4. 至少一次真实模型与至少一次真实工具完成闭环；模拟、真实本地模型、真实云端模型与真实工具分别标明。
5. 任务结束、API 成功、工具退出和漏洞确认使用不同状态，不互相代替。

### 7.3 效果比较

同数据集、相同请求/步数上限，对比“标准流程”“单次 AI 分诊”“Agent 循环”。记录人工裁决后的 Precision/Recall、未验证数、无关/重复请求数、耗时、模型调用、Token、资源使用和有证据的缺陷数。

拟定检测组目标为 Precision >=90%、Recall >=80%，只适用于冻结的窄范围本地数据集；须在 M0 测得基线后核实是否可达。未达到目标不得删减难例后宣称完成；可发布明确标注适用范围的试验功能，但不能默认启用或声称提高实际赏金收益。

首版价值至少体现为：相同预算下比标准流程补充了正确的新证据，或相同检测结果下显著减少无效请求/人工检查。没有增益时，相关阶段继续使用确定性流程。

## 9. 回退方案

- Agent 独立功能开关默认关闭；标准模式和旧报告数据保持可读。
- 每个阶段使用可审查的独立提交，记录基线提交与前一可用版本。普通代码利用 Git 管理，不制造多份全项目副本。
- 数据库新增结构向后兼容；重要迁移前备份到项目目录，旧版本不能误读新状态。
- 发布失败可重新安装前一正式包到独立目录，按恢复说明复用兼容数据；不直接覆盖运行中的文件。
- 回退不删除 API 密文、报告、会话、目标资料或 Docker 数据。
- 不使用 `git reset --hard` 或宽泛清理来完成回退。既有用户修改始终保护。

## 10. 时间与成本安排

实施顺序为 M0 → M1 → M2 → M3 → M4 → M5 → 本地综合验收 → 可选 M6 → M7。M5 的任务详情原型可以在 M1/M2 稳定后提前接入，但最终界面验收依赖真实后端。

粗略工程估算：M0 1–2 人日，M1 2–4 人日，M2 2–4 人日，M3 3–5 人日，M4 2–4 人日，M5 2–4 人日，M7 1–2 人日；M6 另计 3–5 人日。估算不等于承诺，取决于依赖恢复、模型响应速度和基线问题；Agent 执行的实际耗时另测。

优先交付 M1+M2 的最小有用版本，再交付 M3+M5 的 API/业务检查版本，随后完成工具编排、可选真实目标入口及正式发布。每次交付都必须提供实际执行记录和剩余限制。

云端成本按“实际输入 Token ×输入单价 +实际输出 Token ×输出单价”估算，并结合缓存计价、折扣及服务商用量记录核对；标注单价来源和估算时间，不得用模型名字推断价格或把连接测试次数当全部用量。本地模型没有云端 Token 费用，但应测量 CPU、内存和时延。

## 11. 升级后的使用流程

1. 双击桌面启动器，在启动提示中决定本次是否允许云端 AI。
2. 在平台内保存或选择模型；本地模型不可用或云端禁止时，清楚显示可选模式。
3. 先选择本地靶场，查看实际健康状态，选择标准检测或 Agent 检测。
4. 查看任务摘要：目标、范围、动作集合、模型、调用与请求限制；点击开始。
5. 在任务详情查看动作、理由、证据引用与真实结果；必要时停止或处理人工待办。
6. 到候选页查看对照证据与 Agent 建议，由人工确认、驳回或继续保留未验证状态。
7. 查看/导出完整脱敏报告。真实项目在另外确认具体授权后才能执行，补天提交由人工完成。
