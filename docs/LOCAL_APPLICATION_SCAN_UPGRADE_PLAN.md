# SRC-Auto 本机 Web 应用审查升级计划

编制日期：2026-10-05。

状态：**L1–L3 与独立源码审查属于 v0.13.0 发布基线；2026-10-09 工作区已接通 L4-A/B 和专用合成 L4-C 的有限真实闭环，尚未正式发布**。L4 包含目标绑定会话、四角色 JSON 对象对照及固定 SQL/惰性 HTML 正负对照，不包含任意载荷、脚本执行或自动生产隔离证明。准确增量见 [L4 操作说明](L4_PREPARATION_PROGRESS.md) 和 [L4 验收报告](L4_ACCEPTANCE_REPORT.md)，v0.13.0 成绩见 [统一验收报告](CONTROLLED_LOCAL_SOURCE_ACCEPTANCE.md)。本文的设计通过条件不能当作全部已取得的测试成绩。

适用项目：`D:\网络安全文件夹\SRC-Auto`。本计划是 [受控 Agent 总计划](AGENT_UPGRADE_PLAN.md) 的专项扩展，承接 M4 的工具编排、M5 的界面与持久化，以及 M6 的目标权限校验；不替代既有五靶场 Agent 的进度记录。

## 1. 目标、范围与不承诺的能力

新增“本机应用审查”入口，让用户选定一个本机 HTTP/HTTPS 服务，确认范围后完成真实的有限检测、候选研判、证据整理和报告生成。无需开启全局外部真实目标开关，也不能因此获得访问其他端口、其他网站或本机任意文件的权限。

第一版只支持本机 **Web 应用/API 服务**，不是任意 Windows 桌面程序、进程内存、数据库或局域网设备扫描器。量化平台可作为首个应用案例，但不能把一次量化平台验收等同于所有本机应用均已覆盖。

- 首版目标为明确登记的回环 IP 字面量，例如 `http://127.0.0.1:8765`；IPv6 `::1` 必须单独登记。主机、协议和端口精确匹配，不把整个回环网段或 `localhost` 的任意解析结果默认放行。
- 默认只读基线与有限被动分析；不能仅因为方法是 GET 就认为没有副作用。
- 业务权限、IDOR、XSS、SQLi 等受控验证需要明确的用例、测试账号和隔离数据。输入一个网址不能自动推导业务的正确权限规则。
- 源码审查是可选的独立能力，不由网址推断源码目录，不默认读取 `D:\量化交易` 的文件。
- 不承诺发现全部漏洞、无误报或获得赏金；模型结论仍是候选建议，最终裁决由人工负责。

## 2. 当前缺口与可复用基础

2026-10-05 方案审查时源码核对发现的设计缺口（后续修复状态见实施进度）：

| 当前表现 | 后续修正要求 |
| --- | --- |
| 通用执行入口的外部目标硬门会阻止本机自有应用；Agent 动作主要绑定固定靶场 | 增加明确的本机 Web 应用目标类型和目标级许可，不简单开启全局 `allow_real_targets` |
| `scope.py` 用 `bool(value)` 读取确认字段；空端口集合不形成端口限制 | 新范围严格检查布尔值、非空端口和完整约束；字符串 `"false"` 不能变成确认授权 |
| 范围摘要未覆盖路径、方法、时间窗和请求额度等全部执行字段 | 引入版本化范围与任务审批快照，安全字段变化使旧审批失效 |
| 录入草稿已有路径、方法、时间窗等字段，但不等于执行器已强制使用这些字段 | 形成统一的有效执行策略，CLI、Dashboard、Agent 共用同一校验逻辑 |
| `target_urls` 的校验与工具实际 `args` 分离 | 适配器只从批准的结构化计划生成命令；不能让模型或导入文件提供任意命令参数 |
| 通用适配器使用阻塞式 `subprocess.run` 并捕获输出 | 增加受管进程、运行中取消、输出限制和任务级清理，不能仅等待下一阶段停止 |
| 外部工具流水线终点为 `completed_tools` | 接通规范化观察、候选去重、证据、研判及任务关联报告；工具退出不等于漏洞确认 |
| 部分通用输出保存的是工具结果或字符串；报告统一使用补天标题 | 接入本机应用前做落盘前脱敏，报告按任务类型命名并说明覆盖、阻塞和未验证内容 |

继续复用现有目标草稿、ScopeGuard、会话密文库、工具注册表、标准检测、Agent 严格动作契约、SQLite 任务租约、STOP、资源/预算检查、AI 会话硬门、候选裁决和报告查看组件。不新建第二套 Agent 框架或认证/加密机制。

## 3. 目标与授权契约

### 3.1 结构化字段与版本兼容

至少包含：范围版本、目标类型和 ID、协议/IP/端口、允许路径、排除路径、允许方法、自动化许可、带时区的开始/结束时间、并发、请求总量、任务时长、响应/输出上限、检查配置版本和授权说明引用。测试账号使用会话引用，不能把 Cookie 或 Token 写进范围文件。

- 新版本字段严格校验类型与范围，拒绝隐式布尔转换、空端口、无时区日期、未知权限字段和歧义输入。
- 允许与排除规则冲突时排除优先；未列入许可的路径、方法或工具能力默认不允许。
- 全部有效安全约束及配置版本进入规范化摘要。任务绑定不可变快照；编辑草稿不改变运行中任务。
- 旧范围、旧任务和旧报告保持可读；旧配置不能自动升级为本机应用可执行授权。需要执行时引导用户确认新增约束，而不是静默放宽。
- 首版只需对正常录入与异常输入做明确提示，不为历史配置建立无必要的复杂兼容体系。

### 3.2 请求前的真实门控

预检以及每一次实际请求都核对范围、时间窗、STOP、额度和会话有效性。请求预算包括跳转、重试、探测和扫描器内部请求，不以“工具启动一次”代替实际请求数。

- URL 规范化后校验协议、主机、端口和路径；拒绝用户信息段、异常编码及路径歧义。对反斜杠、点段、百分号编码、大小写语义分别提供回归用例，不依靠字符串 `startswith` 判断目录授权。
- 相对跳转先结合原 URL 解析，再校验最终地址；跨协议、跨端口、跨主机或进入排除路径的跳转在发送前拒绝。
- 不因下载页面、JavaScript、OpenAPI 或网页提示而自动访问外域；发现的链接先登记，再经许可检查决定是否访问。
- 云端模型只在明确启用的 AI 阶段访问批准提供商。扫描阶段不得借云端许可开放外部网络或回调通道。
- 时间窗用带时区时间判断；任务超时用单调时钟控制。系统时间异常时明确阻塞，不无限延长任务。

### 3.3 本机应用身份与无副作用原则

启动前核对入口、健康状态与可取得的应用身份信息。端口复用、应用重启或身份与预检记录明显不一致时暂停，避免把原审批用于占用同一端口的另一个程序；响应指纹仅用于变化检测，不能当成可靠身份认证。

量化案例第一轮可从 `/` 和 `/api/health` 的明确只读请求起步。交易、撤单、重置、任务控制、账户、持仓及其他业务敏感路由默认排除，不能自动递归访问首页中所有链接。具体白名单必须以目标实际路由与业务副作用审查为准。

## 4. 检测配置与真实结果链

| 配置 | 工作内容 | 准入条件 |
| --- | --- | --- |
| A：只读基线 | 连通性、响应头、明确许可页面/API 的有限检查 | 授权有效、精确入口、允许路由、有限请求额度 |
| B：有限发现与被动分析 | 有界同源发现、批准请求的 ZAP 被动分析、受限规格检查 | A 验收通过；能证明工具出口、路径、取消和额度控制有效 |
| C：隔离受控验证 | 合成账号权限对照、指定对象 IDOR 辅助验证、最小 XSS/SQLi 验证用例 | 独立配置/数据与测试账号已核验，不连交易/QMT等生产系统；用例另外审批 |
| D：可选源码审查 | 用户指定源目录内的静态检查、配置/依赖风险整理 | 独立选定范围，只读、不执行项目脚本；明确文件与数据发送规则 |

统一流水线：预检 → 真实检测 → 解析与规范化观察 → 候选去重 → 证据充分性检查 → 可选 AI 研判 → 人工复核队列 → 脱敏报告。

实际 HTTP 检测、仅离线分析、静态源码检查和模型建议分别标识。缺响应头属于配置建议；API 契约失败、业务异常、可疑权限差异和经人工确认漏洞不得混为一种计数。

- 候选和报告绑定任务 ID、范围摘要、应用实例记录、检查配置、工具/模型版本和证据引用。
- 必须记录已检查、被阻止、跳过、超时、工具缺失及未覆盖内容。零候选不能显示为“系统完全安全”。
- 部分工具不可用时可以完成已许可的其余检查，但任务显示部分完成及缺失能力，不能伪造完整通过。
- 动态 Agent 流程显示当前阶段、真实动作/请求计数、耗时与待办；总量未知时不制造百分比。
- 对业务权限检查保存预期权限和正/负对照。相同响应、HTTP 200 或模型高置信度都不能单独证明 IDOR。

## 5. 工具、网络与生命周期补充要求

### 5.1 工具出口和运行环境

优先复用本机现有 HTTP 检测与 ZAP 官方 Automation Framework。基线扫描中的爬虫仍会发送请求，不能称为零接触的离线审查。首版对自有实际应用不默认使用整站 Spider、AJAX 浏览器或主动扫描。

- 每个适配器登记支持的范围约束、内部请求计数、取消和超时能力。不能证明强制出口控制有效的工具只允许离线分析或结果导入，不准入自动联网流程。
- 在实际工具接入前验证参数白名单、批准请求入口与必要的出口控制；配置范围不等于进程所有网络出口已受控。
- 固定可信可执行路径、版本、配置/模板摘要，不因 PATH 变化调用另一个同名二进制；插件、模板更新和外部回调不得在任务中自行开启。
- 隔离继承的代理与有关网络环境变量；维持 TLS 证书校验。自签名本地 HTTPS 使用明确配置的可信 CA，不默认 `verify=False`。
- Docker 容器的 `127.0.0.1` 指向容器本身，不能等同于 Windows 主机。首版优先原生工具；若采用容器，单独设计并验收宿主机映射与出口边界，不能简单放行 `host.docker.internal` 或扩大允许网段。
- 工具临时目录、配置缓存和项目产物显式放在 SRC-Auto 指定子目录；无法保证的工具需要标明限制，不宣称完全符合 D 盘约束。

依据：[ZAP Baseline 的爬虫与被动分析说明](https://www.zaproxy.org/docs/docker/baseline-scan/)、[Automation Framework](https://www.zaproxy.org/docs/automate/automation-framework/)、[被动分析等待任务的超时配置](https://www.zaproxy.org/docs/desktop/addons/passive-scanner/job-pscanwait/)。采用版本和插件配置在接入时再次核对，所有等待明确设置上限。

### 5.2 停止、恢复和资源

- 复用现有任务租约、状态库和 STOP；受管进程只清理本任务拥有的进程树，不结束目标应用、Docker 引擎或其他任务。
- 停止操作可以打断当前工具；取消、超时、失败和部分完成保持不同状态，已有合格证据可生成部分报告。
- 重复点击开始必须幂等；同目标默认串行，避免两个任务同时访问同一服务绕过请求/资源限制。
- 暂停与取消语义不同；对不能安全暂停的工具只提供取消。关闭浏览器不等于取消后台任务。
- 重启不自动恢复网络或云端调用；人工继续前重做范围、身份、会话和 AI 许可检查。未知完成状态不自动重放有副作用请求。
- 执行前及每阶段核对 CPU、内存、磁盘、总时长、请求、输出和模型用量。沿用项目现有资源上限，不在本计划中另改全局配置。

## 6. 数据保密、报告与源码目录

### 6.1 脱敏发生在保存前

复用现有脱敏和 DPAPI 能力，但不能仅依赖报告查看时的正则替换。响应正文、命令输出、错误详情、URL 查询参数和模型上下文在进入数据库、事件、证据及报告前统一筛选，默认保存必要字段摘要与证据引用，不保存整站/全量业务数据。

- 会话和模型密钥仅保存密文与引用；不进入命令行、Git、分发包、日志或报告。
- 持仓、资产、交易记录及个人信息默认不采集、不发云端。结构化白名单和合成样本优先；不能保证脱敏时停止发送并提示人工处理。
- 初版复用现有人工云端审阅；后续自动研判仅能使用本次任务批准的数据类别、模型和额度。启动选“否”时所有云端调用路径硬拒绝，保存密钥和刷新页面不产生调用。
- 页面、响应、规格和报告都是不可信数据；提示注入不能改变权限、工具目录或数据发送边界。
- 报告渲染转义不可信内容；不直接执行工具产生的 HTML/脚本。确需查看 HTML 工件时使用受限查看器，不能给报告页面访问平台令牌或执行任务的能力。
- 按“本机应用审查/靶场验收/授权目标候选”命名报告，展示覆盖与证据；预览截断提示与完整脱敏导出保持一致。
- 对新增任务产物明确体积上限、保留/删除机制与导出范围，不自动清除现有报告或备份。发布时同时检查源码、分发包和生成工件排除清单。

### 6.2 隔离副本和源码审查不是同一许可

主动验证的应用副本必须有独立配置、数据库/数据目录与合成账号，核对实际加载路径、启动参数与外联；不能只复制代码后继续使用原 `.env`、原数据、券商连接或原账户。控制流量不能证明业务已经隔离，必须有隔离验收证据。

可选源码审查允许用户单独选定外部源目录，但只读检查；所有输出仍在 SRC-Auto 中。默认跳过密钥、`.env`、业务数据、模型权重、二进制、依赖/vendor及无关大目录。检查 Windows junction、符号链接、重解析点与路径越界；不运行目标的构建、安装钩子或导入执行。访问依赖漏洞库或发送代码片段是另外的数据处理动作，需要明确标识许可，不能隐含在“离线”中。

## 7. 界面与正式使用流程

新增独立“本机应用审查”入口，保留本地靶场、授权外部目标及离线审阅入口。复用现有页面、任务详情、报告查看和内嵌 AI 设置，不再引入层层弹窗。

1. 输入本机服务 URL，选择检查配置；填写/确认允许路由、排除路由、方法和时间窗。
2. 预检显示真实健康结果、应用身份变化、工具可用性及不能执行的检查；不会因为打开页面自动扫描。
3. 在任务摘要看到最终范围、模式、请求/时间限制、数据处理规则和本次模型许可，人工点击开始。
4. 查看当前阶段、实际请求/动作、脱敏事件、阻塞原因及停止按钮；任务事件与候选/报告可直接关联。
5. 查看报告的完整脱敏内容、检查覆盖和未验证条件；人工确认候选，补天提交不自动执行。

前端字段与后端执行 DTO 必须一致；不能出现“表单填写了排除路径，但执行器未使用”的假控制。页面缩放、窄屏、键盘操作、加载/断连/重复点击、中文编码和报告打开均纳入真实交互验收。

## 8. 修订后的实施顺序

| 阶段 | 必须交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| L1：范围与执行器 | 新目标类型、严格范围、统一策略、审批摘要；类型化适配参数、逐请求跳转校验、取消/输出上限 | 门控、兼容、取消回归通过；违规请求发送数为 0；旧靶场和外部禁用开关不回归 |
| L2：最小真实闭环 | 只读基线、本机目标表单、任务详情、规范化候选与直接可读报告 | 自有合成 Web 应用实际请求可追溯；量化入口只执行已批准只读检查；失败/部分结果真实显示 |
| L3：成熟工具与 AI | 有界发现、经验证的 ZAP 被动配置、脱敏研判、可信版本和出口/生命周期控制 | 工具能力逐项验收；同范围对比标准/Agent 的证据质量、请求、耗时及用量；云端禁用实测 0 调用 |
| L4：隔离验证与发布 | 独立副本、合成权限/受控验证用例、可选源码审查，完整说明与发行包 | 正负对照、无业务污染、完整回归及干净安装通过；取得当次发布授权后同步源码和下载版本 |

可选源码审查不作为 L2 的阻塞依赖；工具复杂度过高时先交付可验证的原生只读闭环。新功能未完成的阶段明确标注试验/不可用，不修改已有五靶场成绩或用历史结果代替本轮验收。

## 9. 验收清单与效果口径

实施前将用例编号、输入、期望、证据位置和版本冻结。至少覆盖以下类别，不把表中的要求当成已经通过：

| 类别 | 必须覆盖的用例与证据 |

| 范围/审批 | 未确认、字符串布尔值、空端口、过期时间窗、修改审批字段、跨任务证据、CLI/UI/Agent 一致性 |
