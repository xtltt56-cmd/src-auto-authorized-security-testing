# 自定义本地目标、受控 L3 与源码审查使用说明

更新时间：2026-10-06。适用于本轮升级后的源码工作区；正式发行状态另见 [发布清单](../RELEASE_MANIFEST.md)。本轮没有自动上传 GitHub 或更新下载包。

## 1. 选哪个入口

| 需要做什么 | 页面 | 实际工作 | 是否调用云端 |
| --- | --- | --- | --- |
| 练习既有五个靶场 | 本地靶场 | 保留原有固定靶场任务 | 按原有单任务授权 |
| 检查自己启动的本地 Web 靶场或应用 | 本机应用审查 | 保存目标草稿、审批精确回环范围、有限 GET/HEAD | 标准模式不调用；Agent 模式另行确认 |
| 对批准响应做成熟工具检查 | 本机应用审查 → L3 配方 | 原生执行器收集元数据，ZAP 在断网容器内分析脱敏 HAR | ZAP 不联网；可由已授权 Agent 编排 |
| 审查一个本地源码目录 | 源码安全审查 | Bandit / Semgrep 在断网容器内审查批准快照 | 不调用 AI、不上传源码 |

自定义靶场入口复用本机应用流程，不新建第二套扫描框架。网站测试授权不等于源码目录授权。保存或载入草稿不授予执行权限，不会自动启动应用、访问页面或执行命令。

## 2. 启动与工具准备

日常仍使用桌面 Dashboard 启动器，或在项目根执行：

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto'
.\START_DASHBOARD.bat
```

启动时选择是否允许本次会话云端 AI；选择“否”或回车，服务端拒绝云端调用。保存密钥本身不是调用许可。DeepSeek 沿用「系统设置」中加密保存的配置，API ID 取配置中的 `deepseek-flash`，不根据展示名称猜测。不要把密钥写进目标名、网址或源码目录。

L2 原生只读基线不需要 Docker。L3 与源码审查需要本机 Docker Desktop 已正常启动，并提前准备固定工具：

```powershell
python -X utf8 tools\install_controlled_scanners.py
```

此命令只准备工具，不扫描目标。已有固定镜像及校验通过的 wheels 会复用；缺失时才从指定官方来源下载。镜像固定 digest、Docker CLI 和 wheels 固定 SHA-256；任务运行期间不自动安装、拉取或更新。二进制和 wheels 存于项目 `vendor/`，镜像存于 Docker 配置的数据目录；本机 Docker 数据已在 D 盘。

当前 Docker CLI 配置对应已核验的 Docker Desktop 4.87 / Engine 29.8.0。其他 CLI 校验不匹配时会阻止准备，需要另外核验并更新工具配置，不能仅关闭校验。首次下载需要可用网络；Docker 自己的代理设置也必须有效。此轮已验证本机现有工具的准备流程，尚未在干净客户电脑验证全部可选依赖安装。

## 3. 自定义靶场 / 自有本机应用

1. **先自行启动目标。** 例如已有授权的本地服务 `http://127.0.0.1:8765`。入口必须是精确回环 IP、协议和显式端口；不要输入外域、`localhost`、凭据或查询字符串。
2. 点击「本地靶场」中的自定义目标入口，或左侧「本机应用审查」。在目标库填写名称、用途及下面的入口 / 路由，可保存、复制、载入或删除草稿。
3. 允许路由每行一条，如 `/` 与 `/api/health`。排除路由及其子路由优先。确认这些请求无业务副作用；不要加入交易、撤单、重置、账户、持仓等路由。GET 不自动等于无副作用。
4. 选择配方：**L2 只读基线** 或 **L3 批准范围内链接分析 + 断网 ZAP 响应头检查**。设置带本地时区转换的时间窗、总请求及任务时限。
5. 选择标准模式，或受控 Agent 模式。Agent 首版最多 6 条批准路由；标准范围最多 64 条，仍受总请求预算约束。
6. 勾选拥有授权，点击「核对审批摘要」。此步只核对输入、监听进程身份和已准备工具，不向目标发送 HTTP 请求，也不调用模型。
7. 核对路由、方法、时间窗、额度与监听实例后，再勾选执行确认并点击「开始本机审查」。修改输入、应用重启或审批过期都需重新核对。
8. 在任务详情查看真实步骤、实际请求、响应状态、用量与候选。可停止；中断后不自动重放。点击「查看完整报告」进入平台报告查看器，可导出完整脱敏副本。

载入、复制、新建空白草稿都会清除旧执行授权和云端同意。删除只删除草稿，不删除你的应用、历史报告或任务。

### Agent 使用云端的条件

必须同时满足：启动会话允许云端、页面启用 Agent、单任务选择 DeepSeek 并同意云端分析。拒绝任一条件时，不创建远程模型，不自动切换其他提供商。模型只能选择批准路由编号、断网被动分析、请求人工处理或完成；不能创造 URL、命令、请求头、载荷或扩大范围。

给模型的是有界、脱敏的动作与响应元数据，不是原始正文、Cookie、响应头值或源码。实际调用次数、Token 和估算费用写入任务；费用受原有共享预算账本约束。模型“认为安全”不是事实裁决，完成还必须通过程序侧覆盖检查。

### L3 覆盖与不覆盖

原生执行器只访问已有批准路线，直接连接回环监听，不使用环境代理。跳转必须重新检查并计入额度。HTML 链接分析仅登记已批准同源路径；外域、排除项、带查询参数等链接被拒绝，不通过发现动作新增权限、不自动递归爬取。

ZAP 只导入脱敏 HAR：正文为空、Cookie 为空、响应头只保留存在性占位值。启用三个固定缺失响应头规则 `10020`、`10021`、`10038`；不会判断响应头具体值是否正确，也不运行正文型漏洞规则、Spider、Active Scan、请求重放或自动插件更新。扫描容器 `network=none`，扫描器对目标发起请求数为 0。

这些结果是**配置建议**，不作为已确认漏洞计数。HTTP 5xx 是**功能异常待复核**。不能据此声称完整整站扫描、业务逻辑漏洞覆盖或补天奖励命中。

## 4. 独立源码安全审查

1. 点击左侧「源码安全审查」，填一个具体项目或源码子目录的本地绝对路径。不能直接审查整个磁盘、个人主目录、UNC 路径或目录联接 / 符号链接。
2. 选择 Python 和 / 或 JavaScript / TypeScript，分别勾选目录读取授权与临时快照同意。
3. 点击「核对源码快照」，查看文件数量、总字节、排除计数、摘要和有效期。此步会读取批准语言文件计算摘要，但不执行扫描或调用 AI。
4. 再确认启动离线审查。只将批准文件复制到项目 `runs/source/` 下的任务自有目录，容器只读挂载快照，不挂载原项目；不执行源码、构建、依赖安装或 Git 钩子。
5. 查看实际扫描器 / 规则、相对文件路径、行号及关联报告。结束时删除临时快照和任务自有容器；报告不保存源码片段、密钥值或扫描器原始报文。

默认额度：最多枚举 10000 个条目、批准 2000 个文件、总内容 20 MiB、单文件 1 MiB、任务 300 秒，仅支持 UTF-8。`.git`、`.env`、密钥名称、依赖、缓存、运行数据和构建产物等自动排除；排除数明确展示。CPU 上限仍为 70%、整机已用 RAM 上限 30 GiB，未知指标不放行。

Bandit 1.9.4 当前使用 14 个固定规则，覆盖动态执行、部分硬编码密码、调试、不安全反序列化 / YAML、弱哈希、TLS 校验关闭、shell、SQL 拼接和转义相关风险。Semgrep 1.179.0 使用 4 个已审阅的项目本地 JS/TS 规则：`eval`、`new Function`、部分 shell `exec` 和 `innerHTML` 写入。**不等于完整语言安全规则集或完整污点分析。**

文件、工具或规则在审批后改变时拒绝沿用旧审批；未分析文件、解析错误、超额、取消和工具失败不能显示为“检查全部完成”。零候选仅表示此次已覆盖规则未命中，不代表源码完全安全；可利用性、运行时业务逻辑、依赖 CVE、Git 历史和非批准语言尚未覆盖。

## 5. 常见阻塞

| 提示 / 现象 | 处理方式 |
| --- | --- |
| 时间窗之外 / 审批过期 | 设置当前有效时间窗，重新核对；不通过延长旧任务绕过许可 |
| 应用实例变化 | 确认占用端口的实际应用，重新授权；不自动续跑 |
| 固定工具不可用 | 启动 Docker，执行准备脚本；核对镜像和 CLI 校验，不关闭安全检查 |
| `resource_limit` | 参考报告中的最终 CPU / RAM 采样，降低其他工作负载后重新审批；此轮不放宽限制 |
| STOP / 任务中断 | 明确停止；复查环境、范围和状态后人工重新启动，不重放旧审批 |
| 部分文件未分析 | 看报告里的 `toolErrors` / `unprocessedFiles` 和排除计数，改用较小的正确编码子目录 |

## 6. 重现本轮测试

所有测试使用项目内合成夹具，不读取真实客户源码或量化数据。

```powershell
python -X utf8 tools\validate_local_application_l1.py --phase l2 --full
python -X utf8 tools\validate_passive_integration.py
python -X utf8 tools\validate_source_integration.py
# 下面命令真实调用已保存的 DeepSeek，产生用量，必须由操作者明确允许。
python -X utf8 tools\validate_local_application_cloud.py --execute-cloud --passive
```

准确结果、失败历史和未覆盖项见 [本轮验收报告](CONTROLLED_LOCAL_SOURCE_ACCEPTANCE.md)。测试输出、截图、临时工作区、密文和扫描器二进制均在 Git 忽略目录，不属于公开提交。
