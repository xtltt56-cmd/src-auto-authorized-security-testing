# L4 隔离业务验证：实施与使用说明

更新日期：2026-10-09。上一正式基线：v0.13.0 / f841d90；当前源码准备为 v0.14.0 本地候选版，尚未正式发行或覆盖 GitHub 下载。最新统一实测见 [统一验收](L4_UNIFIED_ACCEPTANCE.md)，下文首次开发验收数字保留为历史记录。

## 已接通的功能与边界

| 阶段 | 当前可用能力 | 限制 |
| --- | --- | --- |
| L4-A | 真实回环 API、SQLite 草稿、Windows DPAPI 测试会话、四角色预期权限规格 | 保存、载入与离线核对不授予执行权限，不自动证明隔离 |
| L4-B | 对批准的 GET 路由执行账号 A、账号 B、管理员、匿名四角色对象对比；标准配方或受控 Agent；真实任务、取消、证据和报告 | 仅精确回环 IP / 端口、同一实例、有效审批与会话；JSON 对象证据不完整时转人工 |
| L4-C | 本项目专用合成靶场的固定 SQL 布尔差异和惰性 HTML 反射正负对照 | 不开放任意载荷；HTML 反射不等于已验证脚本执行的 XSS |
| Agent | 决策、有限工具执行、实际观察反馈、覆盖检查、完成和报告形成闭环；已实际调用 DeepSeek | 不能越过程序侧范围、时间窗、STOP、资源和人工授权门 |

## 最简单的体验方式：启动专用合成靶场

1. 在项目根目录手动运行 `START_L4_LAB.ps1`。也可以在 PowerShell 中执行：

   ```powershell
   Set-Location 'D:\网络安全文件夹\SRC-Auto'
   .\runtime\python\python.exe -X utf8 -u tools\run_l4_lab.py
   ```

   默认端口为 `127.0.0.1:8766`，保持窗口打开；端口占用会报错，不会重置其他应用。需要其他端口时用 `--port 8767`。Ctrl+C 关闭本次合成服务和内存数据库，不删除保存的目标草稿或会话。

2. 启动 Dashboard，进入左侧「业务验证准备」。载入新生成的 L4 合成目标及业务草稿，内含三个加密测试会话、一个有缺陷对象和一个正确保护对象。旧实例草稿不可用于新实例，需载入本次生成的目标。
3. 重新确认隔离声明，点击「离线核对」。该步骤请求 0 次、模型调用 0 次，只核对准备资料。
4. 在同页下方「L4-B / L4-C · 真实业务验证」选择「标准固定配方」，需要时勾选固定合成正负对照；确认本次隔离授权与时间窗，再点击「生成业务执行审批」。时间窗最长 15 分钟。
5. 核对对象、请求上限及模型状态后，另行勾选启动确认，点击启动。两次确认相互独立；修改输入会使预览审批失效。
6. 完整配方实际请求 16 次：两个对象各四角色 8 次，加固定正负对照 8 次。预期产出 3 个未确认候选：对象越权、SQL 布尔差异、惰性 HTML 反射。受保护对象和负对照不应被标为漏洞。
7. 同页可查看四角色状态、权限差异、步骤、调用与 Token 数、取消任务以及打开或下载完整报告。查看页面或报告不会启动请求。
8. 切换 DeepSeek Agent 时，必须同时具备启动时云端同意、页面 Agent 启用与单任务云端同意。保存密钥不等于同意调用，选择禁用不会自动改用云端。

## 使用自己的隔离本地应用

1. 在「本机应用审查」保存自己的隔离本地目标，填写精确回环 IP 和显式端口。排除交易、支付、退出、重置及其他有副作用的路由；业务对照仅使用人工批准的 GET 路由。
2. 自行创建测试账号 A、B、管理员和合成业务对象。在「业务验证准备」填写隔离数据、文件目录标识和人工重置说明。这些文字不会作为命令执行，也不证明生产已隔离。自有应用需登记不同的生产回环入口，避免直接复用原实例。
3. 加密保存三个测试会话，分别绑定目标 ID、入口、角色和有效期，最长 7 天。匿名角色不携带凭据。Authorization / Cookie 输入在保存尝试后清空，不回显、不写浏览器存储、不发给模型。
4. 填写对象 ID、名称、所属角色、精确批准路由，以及四角色预期允许读取的权限。对象 ID 必须匹配响应 JSON 顶层字符串 `id`。
5. 对象所有者的成功响应作为基线；只有对象 ID 一致、完整规范化 JSON 摘要一致且该角色预期被拒绝，才形成越权候选。200 登录页、不同对象、截断、非 JSON 或动态内容差异均不能直接认定漏洞。
6. 保存、载入、离线核对，再按上节两道确认启动。未保存的编辑不参与执行，须先重新保存并载入对应版本。

标准配方最多 20 个对象；Agent 最多 7 个有限动作，启用固定对照后最多 6 个对象。请求预算为每对象 4 次，加可选固定对照 8 次。单请求最长 5 秒、响应正文最多 64 KiB、任务最长 600 秒。模型或目标不可用不会伪造完成。

通用对象对照可用于符合上述约束的隔离本地 JSON API。固定 SQL/HTML 对照只允许本项目登记且实例一致的专用合成靶场，不能对任意自有应用注入载荷。

## 执行门控、存储与隐私

- 审批绑定目标版本、草稿版本、会话内容摘要、监听进程及创建时间、入口和时间窗；任何变化都需重新预览确认。逐请求和接收阶段重查条件，拒绝所有重定向。
- 复用现有单 Agent 执行队列与跨进程任务锁。取消、STOP、资源超限、磁盘不足、会话过期或实例变化均阻断后续请求，不自动续跑。排队失败或报告生成失败会同时结束 Agent 与关联任务记录，不留下假运行状态。同名草稿显示入口和草稿 ID，便于区分实例。
- 继续使用 balanced 资源约束：CPU 70%、整机已用 RAM 30 GiB，并保留已有预算门控。本轮没有放宽这些门控。
- 必须覆盖全部批准对象和必要对照才允许 Agent 完成，不能只看最后一步成功。候选始终未确认、不可自动提交补天。
- 草稿存于 `data/src_auto.sqlite3` 独立表；会话名称和元数据可列出，密文在 `config/sessions/*.dpapi.json`。凭据与绑定上下文一起加密，篡改元数据或降级格式不能重绑定。旧无绑定会话不能直接用于此功能。
- DPAPI 仅当前 Windows 用户及项目上下文可解密，不提供跨电脑凭据迁移。删除草稿不删除目标或会话；删除会话只处理指定密文文件。
- 正文只在内存中有界比较，不落入报告或云端。云端接收有限动作、对象引用和脱敏观察，不接收凭据、原始正文或对象内容摘要；本地报告保留状态、权限规格和摘要证据。
- API 密钥、会话、数据库、验证工件和本机报告被 Git 与分发包排除。项目级 Python 3.12 保存在 D 盘 `runtime/python`；原 Python 3.8 和全局配置未替换。

## 本轮真实云端验收

最新合成靶场对照：`validation/l4-business/20261009-002254-530874/summary.json`，13 项断言全部通过。标准配方完成 16 次本地 HTTP、0 次模型调用、3 个候选，耗时 2.41 秒；DeepSeek Agent 完成同样 16 次 HTTP、4 次实际模型调用、3,564 Token、3 个候选，耗时 5.75 秒。两种模式的对象状态、内容摘要、权限差异和正负对照证据逐项一致，不仅比较候选数量。

该次云端费用按配置估算约 0.008088 元，不是服务商实际账单。第一轮因测试进程未显式设置启动同意而被阻断；修正测试工具的显式云端授权后重新验收，没有取消平台硬门。
