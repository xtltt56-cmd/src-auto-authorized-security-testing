# v0.14.2：剩余运行缺陷修复与验收

日期：2026-10-14。正式发行状态以 GitHub Releases 为准；本文件区分本机代码验收、合成故障注入和真实云端调用，不把它们混作一次全靶场成绩。

## 已处理的问题

1. **模型失败原因笼统**：保留兼容的任务原因 model_unavailable，另记录固定白名单分类，区分凭据、权限、限流、服务、传输、上下文、响应格式/体积与用量异常。不保存异常原文、响应正文、凭据或内部推理。
2. **人工续接残留旧失败警告**：每次新的模型尝试清空当前诊断；历史失败留在脱敏 trace 中。成功恢复后不会继续显示旧的密钥错误。
3. **停止与失败竞争**：模型请求报错时若已收到取消或 STOP，状态优先为 cancelled/operator_stop，不误标可续接暂停。不重试模型或工具，已发送请求的用量仍保守记录。
4. **云端响应无界读取**：远程模型响应最多读取 256 KiB 加 1 字节；超限停止，JSON/编码异常与网络失败分开分类，原始内容不留存。不取消证书校验，不改变已有超时及同意门。
5. **Docker 失败误报容器不存在**：只有对应固定容器名的明确缺失证据才报告 NOT_FOUND。连接错误、超时、坏数据、外来或重复记录都不能授予 READY，也不伪报容器已删除。
6. **五靶场查询串行累计等待**：复用官方 docker inspect 的多名称和格式模板能力，单次 3 秒读取固定名称、状态和健康枚举；不读取环境变量、完整配置或健康日志。网页另有一次 3 秒 Engine 探测，元数据链最坏配置等待约 6 秒，而不是五次 inspect 加长等待。真实启动/执行时限未降低。
7. **失败显示不直观**：任务页直接显示中文诊断和人工处理步骤，可点击进入系统设置，跳转本身没有 API 调用。历史模型失败不会再被重复标成“格式校验”。沿用现有配色与组件，没有新增框架。

## 遇到暂停如何处理

- **凭据/权限问题**：在系统设置保存正确密钥，按本次会话授权由人工连接测试；不要把密钥写进报告、网址或 GitHub。
- **限流/服务/网络问题**：检查服务或已配置代理，原因解除后由人工决定续接或新任务；程序不自动付费重试，不重放未知在途工具。
- **上下文限制**：缩小本次允许路由或对象，重新审批新任务；不能为减小上下文而静默删必查证据。
- **未知用量/大响应/协议问题**：先核对服务商接口和账单，保留失败报告，不将保守额度估算解读为实际扣费。
- **已取消**：不能当作暂停直接恢复；需要人工重新确认新任务。历史已完成观察及失败痕迹仍可查。
- **靶场状态不可读**：核对 Docker Desktop 与 CLI；不因状态不可读而删容器、清理卷、重置数据盘或自动重新下载。

## 没有扩大或承诺的能力

本轮没有继续量化/资管审查，也没有扫描外部目标、开启自动提交、自动切换云端或关闭资源/安全保护。网络故障、云端限流、模型非协议输出和 Docker Desktop 的 Windows 通信缺陷仍可能发生；本轮改善检测、显示、资源边界和恢复流程，不宣称第三方故障被永久根治。未新增 HTTPS/IPv6 的覆盖承诺，不引用旧版全五靶场扫描数字冒充本轮实测。
