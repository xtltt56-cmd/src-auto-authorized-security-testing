# SRC-Auto 三期平台完整使用手册

**适用版本：** 三期升级后的简体中文桌面控制台

**项目目录：** `D:\网络安全文件夹\SRC-Auto`
**核心规则：** 没有明确授权，就不要测试；没有人工复核，就不要提交；不确定时，先停在“离线审阅”。

## 2026-08-28 可视化控制升级补充

当前桌面快捷方式会同时启动两个仅回环服务：前端 `http://127.0.0.1:4173/` 和本地控制接口
`http://127.0.0.1:4174/`。控制台不再使用固定的“运行中”示例数据；它会通过短期进程会话令牌读取
Docker 状态，并每 2 秒刷新一次。首页显示“未连接本地执行服务”或“Docker 尚未就绪”时，表示
没有靶场任务在执行，不能把页面中的历史报告或数字当作当前成绩。

在 **本地靶场** 页面，每个固定靶场都有 **启动、停止、重置、查看任务** 按钮；就绪后才会出现
**打开页面**。页面顶部的 **启动全部靶场/停止全部靶场** 仅对清单中的五个服务逐个提交操作。
这些按钮不接受自定义容器、命令、网址或端口，执行结果和错误会回显为中文状态。任务详情页也提供
同一靶场的启停重置按钮。Docker 不可用时，按钮仍可见，但操作会转为“阻塞/失败”并留下脱敏事件，
不会访问外部目标。

本次实现只增加靶场生命周期和状态可视化，不会自动启动漏洞扫描、登录测试、远程 AI 或补天提交；
扫描/验证仍需沿用后文的人工确认和本地命令流程。

## 1. 先理解平台的用途

SRC-Auto 是一个帮助你组织安全测试流程的控制台，不是自动攻击工具。它把工作分为四条清晰路径：

| 你要做的事 | 从哪里开始 | 是否会自动联网 |
| --- | --- | --- |
| 练习与验证平台 | **本地靶场** | 只访问 `127.0.0.1` 本机靶场 |
| 整理补天项目范围 | **新建授权目标** / **离线审阅目标范围** | 否 |
| 分析两个测试账号/API 响应的差异 | 首页 **测试会话管理** + 命令行 `api-compare` | 默认否；比较器本身离线运行 |
| 整理自有网站的防护观察计划与日志 | 命令行 `defense-plan` / `log-review` | 生成计划和审阅时否 |

不要把“输入了域名”理解成“系统已经开始扫描”。在没有人工确认的范围文件、执行计划与最终执行确认之前，平台应当拒绝接触真实目标。

## 2. 第一次启动：推荐的五分钟流程

1. 双击桌面上的 **SRC-Auto 一键启动** 快捷方式。它启动的是控制台，不是普通文件夹。
2. 在启动提示中选择是否启用远程 AI：
   - 选择“否”或直接回车：本次启动不会调用 DeepSeek、OpenRouter 或 OpenAI。
   - 选择“是”：仅允许后续由你再次确认的一次性审阅；仍不会自动扫描或提交。
3. 进入首页后，点击 **开始本地检测** 进入 **本地靶场** 页面，再按需点击单个 **启动** 或顶部的 **启动全部靶场**，查看所需靶场是否变为“就绪”。
4. 点击首页的 **AI 模型与密钥设置** 查看 AI 入口；工具状态使用项目目录中的 `tool-status` 命令查看，确认所需工具是“可用”而不是“被阻止/缺少依赖”。
5. 先在本地靶场练习“会话、API 比较、报告查看”流程；不要一开始就录入真实补天目标。

如果图形界面暂时无法启动，可在项目目录打开 PowerShell 并运行：

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto'
.\START_SYSTEM.ps1
```

## 3. 首页与导航说明

新版首页的核心入口保持少而清晰：

左侧导航栏的“快速开始、本地靶场、目标与授权、离线审阅、结果与报告、AI 设置”均为可点击按钮；它们与首页对应入口调用同一功能。“快速开始”会把键盘焦点移到第一个本地靶场操作。

| 入口 | 适合什么情况 | 结果是什么 |
| --- | --- | --- |
| 本地靶场检测 | 想先练习、验证安装或回归测试 | 打开本地靶场窗口；只管理固定的本机回环靶场 |
| 新建授权目标 | 已拿到补天项目的明确范围与自动化规则 | 创建待审阅的目标档案，不联网 |
| 本地靶场 | 启动、停止、重置、打开或验证五个靶场 | 仅 `127.0.0.1` |

| 查看 Findings 和报告 | 列出项目内报告与验证工件；单击文件名后在右侧只读预览正文 | 供人工审阅与提交准备；不会执行报告中的链接或脚本 |
| 测试会话管理 | 保存/删除加密的本地测试会话元数据 | 只显示档案名、角色和请求头名称 |
| AI 模型与密钥设置 | 保存 AI 密钥并查看远程 AI 说明 | 配置不会自动启用远程调用 |

攻击面计划、API 比较、权限矩阵、防护观察和日志审阅已经在后端命令中提供；它们当前以项目内 JSON 工件为主，不会因录入域名而自动联网。具体命令见第 6、7 节。

若某个按钮显示“已阻止”“需要人工确认”或“依赖不可用”，这通常是安全设计或环境状态，而不是让你绕过限制的提示。请先阅读该窗口的原因说明。

## 4. 本地靶场：先把平台跑通

### 4.1 五个固定回环靶场

| 名称 | 打开地址 | 主要学习内容 |
| --- | --- | --- |
| Juice Shop | `http://127.0.0.1:3000/` | Web 表面、认证、前端安全与候选整理 |
| DVWA | `http://127.0.0.1:8081/` | Web 安全基础、受控验证练习 |
| WebGoat | `http://127.0.0.1:8082/WebGoat/` | 安全课程与 Web 演练 |
| VAmPI | `http://127.0.0.1:8083/ui/` | API、对象权限、OpenAPI 与响应比较练习 |
| 业务 API | `http://127.0.0.1:8084/health` | 合成订单、GET-only 对象对比、IDOR 候选和固定 OpenAPI 契约 |

所有地址都必须以 `127.0.0.1` 或 `localhost` 开头。若页面跳转到了其他域名，停止操作并不要把该地址加入范围。

### 4.2 常用操作

桌面快捷方式启动控制台后，优先在 **本地靶场** 页面使用可视化按钮：

1. **启动靶场**：只启动所选的固定服务；按钮进入处理中，页面每 2 秒刷新健康状态。
2. **停止靶场**：只停止所选服务，不删除命名卷或项目文件。
3. **重置靶场**：按项目清单移除并重新创建所选服务，可能重置 DVWA 训练数据。
4. **启动全部靶场/停止全部靶场**：按清单顺序逐个提交五个服务，不支持插入其他服务。
5. **查看任务**：打开该靶场的阶段、事件、健康状态和脱敏报告索引；事件不会包含命令、Cookie 或响应正文。
6. **打开页面**：仅在健康状态为“就绪”时显示，地址固定为 `127.0.0.1` 的对应端口。

页面提示 Docker 未就绪时，先启动 Docker Desktop，再点击刷新或重新启动靶场。若需要命令行复核，可使用：

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto'
python -m src_auto local-labs status --human
python -m src_auto local-labs start --lab vampi --human
python -m src_auto local-labs reset --lab vampi --human
```

`READY` 表示容器健康检查和本机 HTTP 检查均成功。第一次启动可能需要 Docker 拉取固定摘要镜像。
在靶场页面完成教学步骤后，再执行本地验证或本地回归命令，让平台生成可审计的本机测试工件。

命令行备用入口：

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto'
python -m src_auto local-labs status --human
python -m src_auto local-labs start --lab vampi --human
python -m src_auto local-validation --local-only --repeat-rounds 2 --human
python -m src_auto local-regression --local-only --repeat-rounds 2 --human
```

本地靶场中的故意脆弱设置只用于练习。靶场的候选数量、ZAP 告警或回归通过率都不能说明真实补天目标存在漏洞，也不代表赏金概率。

### 4.3 业务 API 靶场与对象授权矩阵

`business-api` 是项目自带的确定性合成 API，不是第三方网站。它只监听
`127.0.0.1:8084`，提供 `/health`、`/openapi.json` 和两个合成订单对象；写方法统一返回
`405`，不会修改数据。`buyer-a`、`buyer-b` 和匿名请求的对象响应只用于演示“所有者/同角色/匿名”
比较，矩阵输出只保存状态码和指纹，不保存原始正文。

Docker 运行后可执行一次只读矩阵：

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto'
python -m src_auto business-api-matrix `
  --url 'http://127.0.0.1:8084' `
  --output 'D:\网络安全文件夹\SRC-Auto\validation\business-api\matrix.json' `
  --json
```

看到 `candidate_broken_object_authorization` 只代表辅助比较器发现候选；`confirmed=false`、
`manual_review_required=true` 是固定安全状态。不得增加对象 ID、批量遍历、改变请求方法或把该候选
直接当作补天漏洞提交。当前无 Docker 时可参考进程内单元证据
`validation/business-api/matrix_unit.json`，但它也不替代容器运行验收。

## 5. 录入补天目标：正确的授权流程

### 5.1 录入前准备

在点击“新建授权目标”前，请先从补天项目页或资产所有方准备：

- 明确允许的根域名、子域名、IP 或 URL；
- 明确允许的端口、路径或产品范围；
- 明确排除项，例如第三方 SaaS、CDN 管理面、生产敏感系统；
- 是否允许自动化发现、低速率扫描、登录测试、API 测试；
- 测试时间窗、请求速率限制和应急联系人；
- 用于业务逻辑测试的**专用测试账号**与测试数据范围。

不要将登录密码、Cookie、API 密钥或个人信息写入范围描述、报告备注或截图。

### 5.2 在表单中如何填写

1. 在 **项目代号（小写英文）** 填写一个易识别的代号，例如 `project-2026-08`。
2. 在 **起始网址（HTTPS）** 填写完整的 `https://` 或 `http://` 地址，不能包含用户名、密码或令牌。
3. 在 **允许主机** 中逐个填写授权主机；不要使用“全网”“任意子域”等宽泛描述代替平台规则。
4. 在 **排除主机/路径** 填入平台明确禁止的部分。排除项优先于允许项。
5. 填写授权来源、项目链接/编号和自动化许可说明，便于将来复核。
6. 保存后先使用 **离线审阅目标范围**，核对规范化后的主机、端口、排除项和计划摘要。
7. 只有确认无误后，才按项目规则人工完成 `scope_confirmed.yaml` 和 `live_plan.yaml` 的确认步骤。

保存或离线审阅不会触发外部请求。若系统提示“范围未确认”“目标越界”或“策略禁止”，请回到授权材料修正，不要用修改代码、关闭安全策略或更换 URL 的方式规避。

### 5.3 生成攻击面计划（不执行）

当范围已确认，且项目明确允许自动化观察时，可以生成一个低影响计划。它会列出被动发现、HTTP 存活探测、低深度爬取、受审阅模板的顺序和速率限制，但计划本身**不会执行**。

命令行示例仅用于生成项目内计划文件：

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto'
python -m src_auto surface-plan `
  --target-id 'example-authorized' `
  --url 'https://example.com/' `
  --scope 'D:\网络安全文件夹\SRC-Auto\config\targets\example-authorized\scope_confirmed.yaml' `
  --automation-allowed `
  --output 'D:\网络安全文件夹\SRC-Auto\validation\example-authorized-surface-plan.json' `
  --human
```

请将其中的示例域名替换成平台明确授权的真实范围，且只在满足所有授权条件后继续。真实工具执行必须在控制台或受控命令中进行最终人工确认；不要用这份手册中的示例绕过平台的实时策略门。

## 6. 业务逻辑与 API 权限比较

### 6.1 什么时候使用

此功能适合检查以下问题的**候选证据**：

- 同一笔测试订单、工单、文件或资料，是否被另一个测试账号读取；
- 管理员、普通用户、未登录用户在同一明确资源上的响应是否符合预期；
- API 更新前后是否出现了不应出现的字段或角色可见性变化；
- 状态迁移、字段可见性、重复提交/幂等逻辑是否符合人工定义的业务规则。

它不适合做批量 ID 枚举、猜测相邻编号、跨租户数据收集、自动修改生产对象或密码/令牌测试。

### 6.2 保存测试会话

1. 在首页打开 **测试会话管理**（也可使用 `python -m src_auto session-list --human` 查看非敏感元数据）。
2. 新建档案时填写：档案名、测试角色、请求头名称和值。
3. 只使用项目/资产方提供的测试账号与测试对象。
4. 保存后，系统应仅展示档案名、角色和请求头名称。会话值由当前 Windows 用户的 DPAPI 加密。
5. 若账号失效或项目结束，删除对应档案；不要在普通文本文件保留令牌副本。

在命令行中只能查看非敏感元数据：

```powershell
python -m src_auto session-list --human
```

### 6.3 收集三份最小响应快照

针对一个已明确的测试对象，准备三份项目内 JSON 文件：对象所有者、另一个测试账号、未登录。每个文件的最小格式是：

```json
{
  "status_code": 200,
  "headers": {"Content-Type": "application/json"},
  "body": {"id": "测试对象", "owner": "测试账号"}
}
```

不要把真实令牌、Cookie、密码或大段个人资料放入示例文件。平台比较输出会隐藏敏感字段和正文值，但输入文件本身仍应视为敏感材料并只保存于项目目录。

### 6.4 比较与人工复核

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto'
python -m src_auto api-compare `
  --owner 'D:\网络安全文件夹\SRC-Auto\validation\api-owner.json' `
  --peer 'D:\网络安全文件夹\SRC-Auto\validation\api-peer.json' `
  --anonymous 'D:\网络安全文件夹\SRC-Auto\validation\api-anonymous.json' `
  --output 'D:\网络安全文件夹\SRC-Auto\validation\api-comparison.json' `
  --human
```

看到 `candidate_broken_object_authorization` 时，不要立刻提交漏洞。你仍需要逐项确认：对象属于谁、两个账号是否确实属于不同权限/租户、项目是否允许该对象验证、响应是否因缓存/测试数据造成假象、是否存在最小影响复现。

若只想查看两个对象结构变化，可使用 `api-object-diff`。该操作离线完成，只输出 JSON 路径，避免把原始对象值带入报告。

## 7. 自有网站的防护监测

桌面左侧的 **蓝队被动分析** 入口只登记自有/受托域名、授权证据和是否允许低速观察；勾选不足时始终保存为待授权草稿。
登记动作不联网，日志导入也只读取项目目录内副本，所有处置建议都需要人工执行。

### 7.1 如何生成自有资产防护计划

只用于你自己拥有、负责运维，或有明确内部授权的域名。输入域名后，先把它作为“待确认资产”，不要把补天第三方项目混进自有资产路径。

在资产登记表中必须填写：

- 精确域名，例如 `portal.example.com`；不接受通配符；
- 归属/授权来源，例如资产清单编号、工单或批准记录；
- 已确认归属；
- 已确认允许自动化观察。

在项目内准备一份资产登记 JSON（例如 `validation/owned-asset.json`），再执行：

```powershell
python -m src_auto defense-plan `
  --asset 'D:\网络安全文件夹\SRC-Auto\validation\owned-asset.json' `
  --output 'D:\网络安全文件夹\SRC-Auto\validation\owned-defense-plan.json' `
  --human
```

生成的防护计划只是一份观察清单。它不自动执行 DNS/TLS/HTTP 扫描，更不会改 WAF、防火墙、云安全组或封禁 IP。

### 7.2 导入日志并查看摘要

1. 将需分析的日志**复制**到项目内的受控目录，例如 `validation\logs\`；保留原始日志不动。
2. 将其转换或导出为 JSONL：一行一个 JSON 对象，至少可包含 `status`、`path` 和 `ip`。
3. 使用 `python -m src_auto log-review`，选择项目内文件并设置合理的最大事件数；该功能当前以命令行为主。
4. 查看状态码类别、高频路径、哈希化客户端指纹和异常信号。
5. 把修复建议交给运维/安全负责人，由人执行配置变更。

命令行备用示例：

```powershell
python -m src_auto log-review `
  --input 'D:\网络安全文件夹\SRC-Auto\validation\logs\access.jsonl' `
  --output 'D:\网络安全文件夹\SRC-Auto\validation\logs\access-summary.json' `
  --max-events 10000 `
  --human
```

日志报告不会保留完整查询串、请求头、请求体或原始客户端 IP；它使用哈希化指纹辅助聚合。

## 8. AI 设置与 API 密钥

### 8.1 启用规则

- 启动时选择“否”：当前会话不调用远程 AI。
- 启动时选择“是”：仍需在每次远程审阅前预览脱敏内容并确认摘要值。
- 本地模型与远程模型均只处理候选解释；它们不能启动扫描、改变范围、确认漏洞或提交报告。

### 8.2 保存密钥的正确方法

在 Dashboard 左侧进入 **系统设置**，直接选择 DeepSeek、智谱或 OpenRouter，粘贴密钥并确认模型 API ID 后保存；不再跳转独立输入窗口。密钥由当前 Windows 用户的 DPAPI 加密，项目外的用户不应能直接读取。保存过程不联网，保存成功后明文输入框会立即清空。

需要验证连接时，必须单独勾选 **允许本次联网测试**。该许可只对当前一次点击有效，仅发送固定的“OK”测试文本，可能产生少量费用；它不会启用后台调用，也不会发送目标、报告或 Finding 内容。

请遵守以下做法：

- 只在专用输入框粘贴，不要发到聊天、工单、截图或 Markdown 报告。
- 不要把密钥写进 `.ps1`、`.py`、`.json`、环境变量截图或 Git 提交。
- 一旦误发密钥，立即在提供商后台撤销并创建新密钥。
- ChatGPT Plus 不提供 OpenAI Platform API 密钥；若选择 OpenAI Provider，需要单独的 API 账户与计费安排。

## 9. 查看结果、准备报告和提交

“结果报告”中应把信息分成四类：

1. **运行状态**：已完成、已阻止、等待人工确认、依赖不可用；
2. **候选 Finding**：只代表工具或比较器观察到的现象；
3. **证据工件**：范围摘要、最小化请求/响应指纹、时间、工具版本和复核记录；
4. **人工报告草稿**：影响、前置条件、最小复现、修复建议与平台规则核对。

提交补天前，请逐项完成：

- 确认目标、端口、路径和测试时间都在允许范围；
- 只保留最小化且不含敏感数据的复现证据；
- 再次人工复现，排除缓存、测试数据、角色配置和扫描器误报；
- 用自己的语言说明影响与修复建议；
- 由你本人登录补天平台并手动提交。

SRC-Auto 不会自动点击提交、不会替你选择漏洞等级、不会联系厂商，也不会将本地靶场结果包装成补天报告。

## 10. 安全停止、恢复与故障排查

### 10.1 立即停止

如果发现范围有误、平台规则变化、服务异常或你不确定是否允许继续：

1. 对正在运行的本地流程按 `Ctrl+C`，或关闭对应的前台终端窗口；也可使用 `python -m src_auto stop --human`；
2. 关闭任何浏览器中的真实目标页面；
3. 不要再次确认执行，也不要试图换一个 URL 继续；
4. 保存当前范围和工件，以便人工复核。

命令行备用：

```powershell
python -m src_auto stop --human
```

恢复本地靶场练习时，可使用 **恢复** 或 `resume --local-lab`；真实目标不应因为“恢复”而绕过任何新的人工授权。

### 10.2 常见提示

| 提示/现象 | 含义 | 正确处理 |
| --- | --- | --- |
| `scope_not_confirmed` | 范围文件未确认 | 回到授权材料核对；不要强行运行 |
| `scope_hash_mismatch` | 运行记录与范围版本不一致 | 重新审阅当前范围和计划 |
| `blocked_policy` | 真实目标策略仍关闭 | 这是预期安全状态；仅在项目明确允许且人工复核后按受控流程处理 |
| `tool unavailable` / `blocked` | 工具缺失、被防护阻止或依赖不满足 | 查看工具状态；不要关闭防护或下载未知替代程序 |
| `BLOCKED_HEALTH_TIMEOUT` | 本地靶场未在等待时间内健康 | 检查 Docker Desktop、端口占用和容器日志 |
| 中文显示异常 | 终端编码或字体问题 | 优先使用图形界面；命令行加 `--human`，必要时使用 `--json` 供脚本读取 |
| 远程 AI 未启用/密钥缺失 | 本次不会调用外部模型 | 在设置中人工启用并确认密钥状态，或保持禁用 |

## 11. 你不应该用本平台做什么

- 对未获授权的网站、IP、应用或 API 进行扫描、爬取、枚举或漏洞验证；
- 账号爆破、验证码绕过、凭据填充、密码猜测或批量登录；
- 猜测/遍历连续对象 ID、批量收集用户数据、跨租户读取信息；
- 破坏性写入、删除、支付/订单操作、拒绝服务、弹窗骚扰或影响生产业务；
- 自动向补天或任何平台提交漏洞；
- 向远程 AI 上传密钥、Cookie、完整用户资料、生产日志或未经脱敏的响应正文。
