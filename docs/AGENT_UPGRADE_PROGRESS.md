## 2. 实际新增能力

执行链为：人工启用并启动 → 模型提出下一动作 → 严格契约与引用校验 → 范围/资源/额度/STOP 检查 → 固定只读执行器 → 脱敏观察/候选与检查点 → 下一轮或转人工。

当前动作包括响应头元数据、有限同源静态表面发现、读取本地 API 规范、Business API 合成对象授权比较、读取关联候选、结束与转人工。`read_observation` 未作为执行能力授予；已有观察在有界上下文中提供。

安全与可靠性修正：

- 默认关闭、单并发；SQLite 原子领取任务和进程身份/实例租约，防止第二实例篡改或并行执行。
- 进程退出后只标为中断，不自动续跑；状态无法核实不假定进程已死。Windows 只用只读进程 API，不用可能杀进程的 `os.kill(pid, 0)`。
- Agent 状态库无法读取时明确禁用该模块、保留原文件，不阻断既有标准 Dashboard，也不删除数据库来制造成功。
- 人工续接保留旧计数和额度，并绑定范围、配置、候选、动作版本；配置变化要求新建任务；在途工具结果未知不自动重放。
- 严格四字段 JSON，一次格式修正；未知动作/引用/证据、任意 URL/命令和重复动作都被阻止。
- 每个 HTTP 请求固定本机同源、GET、有限合成账号；不使用系统代理、不过界重定向、不访问规范中的远程引用，响应体最多64 KiB且不进入持久化观察。
- 模型简述不是事实裁决；所有候选 `confirmed=false`、`submission_ready=false`。结束提议必须引用该模式的必要观察。
- 云端循环因费用治理与真实调用未验收，在前后端明确关闭；既有人工云端复核/连接测试不变。已同意启动云端也不会绕过这个阶段门。
- 资源未知不放行；本地模型请求最多120秒，云端最多90秒，无隐式失败切换或自动付费重试。
- 候选沿用标准 Store 去重与关联，报告沿用 Dashboard 的项目白名单和脱敏查看/导出。

## 4. 本地模型探索与当前限制

### 接入资源守卫前的探索

任务 `5804fd407d874e119e0648e552795e02` 在本机固定 Business API fixture 上真实执行：7 个工具动作、15 次 HTTP 请求、8 次本地模型调用、7,116 Token，形成4条待复核候选观察。

这证明出现过“真实模型选择 → 真实工具 → 观察反馈 → 下一动作”的循环，而非前端动画。但它发生在资源守卫接入前、候选标准入库接线前，**不作为当前配置的最终验收，也不宣称这4条观察已在该轮写入标准候选库**。该模型结束简述还与候选观察不一致，因此程序不得用模型话语替代工具结果或人工裁决。

### 带资源守卫的新任务

任务 `3a5c0c82ac29409397e40b5f7dfffa42`：`paused / resource_limit`，0 个工具动作、0 次目标 HTTP、1 次本地模型调用、567 Token。实际采样整机已用内存约28.36 GB、CPU约44.83%，超过 balanced 内存20 GB上限。

## 5. Docker 阻断

本机 Docker Desktop 4.91.0 的日志指向初始化 Ingest UNIX socket 失败：`sailor-ingest.sock` 重命名到 `.stale` 时出现 `The file cannot be accessed by the system`，Linux engine 命名管道不可用。尝试正常启动/停止未恢复。

同类错误已出现在 [Docker Desktop 官方反馈 issue #554](https://github.com/docker/desktop-feedback/issues/554)。这是诊断线索，不证明本机根因已经定位或修复；本轮没有执行 factory reset、删除VHD、回退程序或清理C/D盘 Docker 数据。

本机原生 Business API 进程只用于固定回环探索，不用它冒充“五个 Docker 靶场就绪”。恢复 Docker 后还须逐靶场重新验收，不使用历史 READY 报告顶替。

## 6. 工程位置与复用

- `src_auto/agent_contracts.py`：动作/证据契约、强制额度。
- `src_auto/agent_provider.py`：既有 Ollama / 云端 provider 的动作选择接口；本地结构化输出参考 [Ollama 官方 structured outputs](https://docs.ollama.com/capabilities/structured-outputs)。
- `src_auto/agent_actions.py`：程序拥有的本地只读 recipe、逐请求校验、候选入库与报告关联。
- `src_auto/agent_runner.py`：反馈循环、独立SQLite检查点、原子任务租约、恢复与报告。
- `src_auto/agent_resources.py`：Windows实际CPU/内存测量，复用 ResourceGuard 和 balanced 限制。
- `src_auto/agent_service.py`：人工 Dashboard 执行入口，与原检测共用互斥锁。
- `dashboard/src/pages/AgentPage.tsx`：中文 Agent 控制与轨迹；原报告页负责正文与导出。
- `lab/business-api/app.py`、`config/agent/permissions.json`：固定合成对象及权限规格。
- `tests/test_agent*.py`、`AgentPage.test.tsx`：边界与反馈回归。

没有新增 LangGraph、AutoGen、MCP 通用工具执行器等依赖；当前循环有界且单 worker，已有组件与 Python 标准库足够。外部扫描器继续等待出口验证，不以复制框架代替安全验收。
