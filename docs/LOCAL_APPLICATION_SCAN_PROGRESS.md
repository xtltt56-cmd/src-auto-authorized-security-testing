## 已实现

- 左侧新增 **本机应用审查**。可填写精确回环 IP 与显式端口、允许/排除路由、GET 或 HEAD、带时区时间窗、请求/时间上限。
- 明确授权 → 核对审批摘要 → 再确认实际执行。预览只核对范围和操作系统监听实例，不向目标发 HTTP 请求，也不调用 AI。修改表单使旧审批失效；审批有有效期且不能重放。
- 复用既有 Agent 服务、动作契约、SQLite 状态、会话鉴权、资源/云端预算守卫和报告查看组件，没有建立另一套 Agent 框架。
- 标准模式不创建模型、不调用云端。Agent 模式只能选择最多 6 条已批准路由的编号，不能创造地址、命令、请求头或载荷；每次模型调用前后及每条请求前重查时间窗、STOP 和监听实例。
- DeepSeek 同时要求启动会话允许、Agent 已启用和本任务云端同意。拒绝时零模型调用，不自动切换提供商。API ID 使用当前已保存的 `deepseek-flash` 配置，不由展示名称推断接口名称。
- 原生 HTTP 直连，无环境代理、Cookie、爬虫或自动重试；跳转重新校验并计入请求上限。读取上限、串行执行、资源门槛、超时和取消沿用 L1。
- 保存实际请求数、观察、HTTP 状态、工具轨迹、Token 和终止原因。仅保存响应元数据，不保存正文、响应头值、Cookie。模型简述明确不属于事实裁决。
- 报告与标准运行记录和 Agent 任务关联，可直接查看并导出脱敏副本。覆盖按批准路由编号计算；提前结束、排除跳转、应用重启或报告失败不伪装成功。
- HTTP 5xx 标为 **功能异常待复核**，不是已确认漏洞；缺失响应头是配置建议，不计算漏洞。所有结果保持 `confirmed=false`、`submissionReady=false`。
- 首版仍只支持精确 ASCII 路由，不接受查询参数、编码路径、通配符、登录会话或整站发现。GET 也可能有业务副作用，需由所有者核对路由。

主要新增文件：`src_auto/local_application_workflow.py`、`dashboard/src/pages/LocalApplicationPage.tsx`、对应测试及 `tools/validate_local_application_cloud.py`。L1 范围与执行契约保持在 `local_scope.py` 和 `local_application.py`。

## 使用方法

1. 自行启动拥有授权的本机 Web 应用，确认目标端口和无副作用路由。
2. 正常启动 Dashboard，点击左侧 **本机应用审查**；原生应用检查不依赖 Docker，也不会自动启动目标应用。
3. 输入服务入口与允许/排除路径，设置时间窗和额度，勾选明确授权。先选标准只读模式熟悉流程。
4. 如需云端，在启动器允许本次云端会话，选择受控 Agent / DeepSeek，启用 Agent 并勾选本任务云端同意。复用系统设置中的加密密钥；密钥缺失时先在系统设置保存，不能填写在目标表单或 URL 中。
5. 点击核对审批摘要，检查范围、方法和额度，再确认启动。任务详情显示实际观察与轨迹，可停止；中断后需要重新审批，不自动续跑。
6. 点击查看完整报告，并由人工判断候选与下一步。报告并非补天自动提交；量化应用不得加入交易、撤单、重置、账户、持仓等路径。

## 重现验收

在项目根目录使用兼容的 Python 3.8+：

```powershell
python -X utf8 tools\validate_local_application_l1.py --phase l2 --full
# 下条会真实调用已配置的 DeepSeek，产生费用；仅自建合成应用。
python -X utf8 tools\validate_local_application_cloud.py --execute-cloud
```

单元套件默认禁止真实云端，提供商用假传输明确测试各自门控；云端脚本单独明确授权、使用原项目 DPAPI 密钥和共享预算台账，不复制密钥。验收数据库、报告、截图和 `config/targets/local-web-*` 均被 Git 忽略。发布包的目标配置白名单不包含这些运行生成目录。
