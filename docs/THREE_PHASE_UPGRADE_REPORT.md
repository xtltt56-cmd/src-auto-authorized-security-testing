# SRC-Auto 三期升级交付报告

**版本：** 2026-08-24 验收更新

**项目目录：** `D:\网络安全文件夹\SRC-Auto`

**适用范围：** 已获授权的补天/SRC 目标、已获确认的自有资产，以及固定的本机回环靶场。
**阅读方式：** 本报告说明平台已交付的控制能力、运行边界和验收方法；最终的机器测试结果应以 `TEST_REPORT.md`、`validation/` 下的最新工件及桌面控制台中的“结果报告”为准。

## 1. 交付结论

SRC-Auto 已从“本地靶场控制台”扩展为一个以**人工授权、失败关闭和可复核工件**为前提的安全测试控制层。三期能力覆盖：

| 阶段 | 交付能力 | 设计原则 |
| --- | --- | --- |
| 一期：攻击面与技术检测 | 工具状态、受控资产发现计划、资产快照与差异 | 先生成计划，默认不联网、不执行 |
| 二期：业务逻辑辅助验证 | 加密测试会话、API 响应比较、对象差异和权限矩阵 | 只产生待人工复核的候选，绝不自动确认漏洞 |
| 三期：防护监测 | 自有域名登记、观察计划、防护快照和本地 JSONL 日志分析 | 先证明归属，封禁与配置变更只给建议、不自动执行 |

它不是“自动赚钱”或“自动提交赏金”的系统。平台不会保证发现漏洞、平台受理、获得赏金或产生收入；更不会绕过平台规则、暴力枚举、爆破账号、拒绝服务、自动利用或自动提交报告。

## 2. 不可绕过的安全边界

平台采用“默认拒绝”而不是“默认扫描”。以下门控共同决定一个真实目标是否允许执行：

```text
目标域名/URL
    │
    ├─ 补天或资产方公开范围、自动化许可、排除项已由人工核对
    ├─ scope_confirmed.yaml 已人工确认，且允许网络接触
    ├─ live_plan.yaml 已逐项人工审阅，且人工执行确认已填写
    ├─ 项目策略允许真实目标执行
    └─ 操作者再次使用显式执行动作
            │
            └─ 才可能启动受限工具；任一项缺失即阻止
```

重要限制如下：

- “新建目标”“离线审阅目标范围”“生成攻击面计划”都不等于已授权，也不会因为输入了域名而自动发起网络请求。
- 只允许写入项目目录；报告、日志导入副本、会话密文、快照和验证工件均应放在 `D:\网络安全文件夹\SRC-Auto` 内。
- 外部发现计划限定低速率、低并发、明确目标；Nuclei 仅包含经过审阅的 `ssl`、`misconfig`、`exposure` 标签，并禁用 Interactsh、未签名模板和高风险能力。
- 业务逻辑写操作默认被拒绝。只有测试账号、测试对象、人工确认、范围门控均满足时，才允许测试性的 `POST`、`PUT` 或 `PATCH`；`DELETE`、`CONNECT`、`TRACE` 始终被拒绝。
- 所有业务逻辑、XSS、SQLi、越权或扫描器结果都只是候选证据。提交前必须人工复现、评估影响、核对范围并由人工撰写/提交报告。
- 远程 AI 仅用于人工触发的一次性审阅，不决定授权、不执行测试、不自动提交，也不应接收密钥、Cookie、令牌、完整响应正文或个人信息。

## 3. 一期：攻击面和常见技术风险的受控工作流

### 3.1 成熟工具的适配方式

平台把成熟工具作为独立适配器，而不是重新实现扫描器。配置来源为 `config/integrations/tool_profiles.json`，版本与当前适配状态记录在 `tools.lock.yaml`，安装/状态工件放在 `validation/tools/`。

| 工具 | 在平台中的角色 | 默认使用方式 | 运行注意事项 |
| --- | --- | --- | --- |
| Subfinder | 被动子域资产发现 | 仅在已授权范围的计划中使用 | 发现结果仍需范围过滤 |
| httpx | 低速 HTTP 存活与元数据探测 | 单并发、低请求速率 | 不保存大段响应正文 |
| Katana | 低深度页面/端点发现 | 低深度、低并发 | 重定向必须重新核对范围 |
| Nuclei | 受审阅模板的候选检测 | `ssl`/`misconfig`/`exposure` 低风险标签 | Windows 本机二进制可能被端点防护阻止；可使用已核验的 Docker 回退包装器 |
| OWASP ZAP | 本地靶场被动/受控快速扫描 | 本地靶场优先；主动模式需额外人工确认 | 结果默认保持 `POSSIBLE` 或 `NOT_VERIFIED` |
| BBOT | 被动外部攻击面辅助 | 仅被动/EASM 预设 | Windows Python 依赖可能不可用；可使用 Docker 回退包装器 |
| Schemathesis | OpenAPI/GraphQL 规范驱动的 API 冒烟验证 | 本地或明确授权环境 | 不用于无边界模糊测试 |
| testssl.sh | 受限 TLS 配置观察 | 固定目标、有限检查 | 本机依赖不完整时使用 Docker 回退包装器 |
| reconFTW | Linux 编排器参考项 | 默认禁用 | 不是当前 Windows 工作流的一部分 |

“工具存在”不等于“工具可用”。每次运行前应在控制台查看工具健康状态，或执行：

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto'
python -m src_auto tool-status --human
```

如果端点防护阻止某个二进制，系统应显示阻止状态而不是规避安全软件。不要添加白名单、关闭防护或将未知二进制放到系统目录。

### 3.2 资产快照与变化报告

攻击面计划由 `surface-plan` 生成，输出只包含待执行顺序、命令参数、速率上限和范围内根 URL；计划字段 `execute=false`，并标记 `manual_execution_required=true`。资产快照只保留以下最小元数据：

- 主机、端口、URL、协议/资源类别；
- 状态码、标题、服务端标识、TLS 签发者与到期时间、有限技术标记；
- 新增、消失、未变化资产的指纹差异。

系统不把完整页面、认证头、Cookie 或大段响应正文写入资产快照。差异报告提示人工检查，不会自动判定“漏洞”。

## 4. 二期：测试会话、API 对象与业务逻辑候选验证

### 4.1 DPAPI 测试会话保险箱

测试账号会话以 Windows 当前登录用户的 DPAPI 加密方式保存于项目内的 `config/sessions/`。密文与项目根路径绑定；复制到其他 Windows 用户或其他项目目录时不能直接解密。

- 会话档案仅应存储测试账号的请求头，例如 `Authorization` 或 `Cookie`；不要存储生产管理员密码。
- 控制台列表只显示档案名称、角色和请求头名称，不显示请求头值。
- API 密钥、Cookie、会话令牌和密码不会被写进常规报告、SQLite 摘要或控制台日志。
- 删除会话档案只删除指定档案；应优先使用控制台或项目内受控操作，而不是手动复制密文文件。

### 4.2 API 对象比较与 IDOR/越权辅助判断

该部分不是“自动 IDOR 扫描器”，而是帮助人工用两个**已获许可的测试账号**比较同一个明确对象。工作流如下：

1. 只选择由对象所有者响应返回的对象 ID，或人工录入的测试对象 ID；系统不生成相邻 ID、不枚举对象。
2. 分别采集“对象所有者”“另一测试账号”“未登录”三个响应快照。
3. 使用离线比较器去除 `token`、`cookie`、`authorization`、`password`、`secret` 等敏感字段及操作者指定的易变字段。
4. 输出状态码、结构/内容指纹是否等价、JSON 路径差异和候选结论；不输出正文中的值。
5. 只有人工复现并确认对象归属、影响和平台规则后，才可将候选转为报告材料。

比较器的结论只有三类：

| 结论 | 含义 | 自动确认？ |
| --- | --- | --- |
| `authorization_enforced` | 对等测试账号收到 401/403 等拒绝 | 否；只是记录该控制有效 |
| `candidate_broken_object_authorization` | 两个已登录账号对明确测试对象得到等价成功响应 | 否；必须人工复核对象、租户和业务规则 |
| `inconclusive` | 响应不满足上述任何保守条件 | 否；需要人工补充证据 |

权限矩阵会把每条用例独立记录，保留预期角色，不会把多个对象或账号混为一个结论。所有矩阵报告的 `confirmed_findings` 固定为零，除非人工在系统外完成复现与审核。

### 4.3 本地 API 靶场：VAmPI

本地靶场新增成熟的 VAmPI API 演练应用，固定镜像摘要并仅绑定回环地址：

| 靶场 | 本机入口 | 用途 | 边界 |
| --- | --- | --- | --- |
| OWASP Juice Shop | `http://127.0.0.1:3000/` | Web 应用表面、认证与前端安全练习 | 仅本机回环 |
| DVWA | `http://127.0.0.1:8081/` | 常见 Web 漏洞练习 | 仅本机回环 |
| WebGoat | `http://127.0.0.1:8082/WebGoat/` | 安全课程与业务安全练习 | 仅本机回环 |
| VAmPI | `http://127.0.0.1:8083/ui/` | API、对象访问与规范驱动测试练习 | 仅本机回环；应用自身故意处于脆弱训练模式 |

VAmPI 的脆弱行为是靶场设计的一部分，只能用于验证控制台的会话、响应比较、权限矩阵和 Schemathesis 本地冒烟流程。不得把靶场中的路径、账号或行为模式直接套用到真实目标。

## 5. 三期：自有资产防护监测

### 5.1 资产登记与观察计划

“添加自有域名”首先创建**待确认资产档案**，不会访问网络。要生成防护观察计划，档案必须同时包含：

- 合法的精确域名（不接受 `*.example.com` 通配符）；
- 可复核的归属/授权来源，例如内部资产清单编号或负责人授权记录；
- `confirmed_owned=true`；
- `allow_automated_observation=true`。

计划的设计上限为 1 请求/秒、单并发，并只列出 DNS/TLS/HTTP 响应头快照、资产差异与本地日志审阅。它不包含账号测试、内容修改、利用、拒绝服务、影响证明、自动封禁、防火墙修改或云配置修改。

### 5.2 防护快照和日志分析

防护差异比较只返回 JSON 路径层面的新增、移除、变化，不回显 `body`、`response_body`、`authorization`、`cookie`、`token` 或 `secret`。本地日志审阅目前面向项目内导入副本的 JSONL 日志，受最大事件数限制，输出：

- 状态码类别计数；
- 去除查询串后的高频路径；
- 经过哈希处理的客户端指纹，而非原始 IP；
- 4xx/5xx、格式错误行等需要人工检查的信号；
- 仅供人工采用的修复建议方向。

系统不修改原始日志，不上传日志，不自动封禁任何地址。

## 6. AI 与隐私处理

平台的 AI 作用是“人工审阅候选”，不是扫描器、授权系统或漏洞确认器。

- 本地 Ollama 模型可作为本地分诊/解释能力；性能受本机 CPU/GPU 与模型大小影响。
- DeepSeek、OpenRouter 或 OpenAI 路径必须由操作者在启动时明确同意，并在每次远程审阅前查看脱敏预览与摘要确认值。
- API 密钥应使用当前 Windows 用户的 DPAPI 加密保存；不要在聊天、报告、截图、命令历史或源代码中粘贴密钥。
- ChatGPT Plus 订阅不等同于 OpenAI Platform API 密钥；如需 OpenAI API，必须另行取得并承担相应费用与数据处理责任。
- 禁用 AI 或在启动提示中选择“否”时，本次会话不应调用任何远程 AI。

## 7. 本地验证、稳定性和证据

平台的验收原则是：**功能主张必须对应可复跑证据，环境阻止必须如实显示。** 推荐按以下顺序验证：

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto'

# 1) 代码级回归
python -m unittest discover -s tests -v

# 2) Python 语法/导入检查
python -m compileall -q src_auto tools tests

# 3) 工具状态（不会开始真实目标扫描）
python -m src_auto tool-status --human

# 4) 四个本地靶场状态
python -m src_auto local-labs status --human

# 5) 仅回环的固定验收与回归
python -m src_auto local-validation --local-only --repeat-rounds 2 --human
python -m src_auto local-regression --local-only --repeat-rounds 2 --human
```

| 阶段 | 重点单元测试 | 本机/界面验证 | 通过的含义 |
| --- | --- | --- | --- |

| 二期 | `tests.test_session_vault`、`tests.test_business_logic`、`tests.test_upgrade_cli` | VAmPI 回环靶场、三份本地响应快照比较 | 会话不会明文列出，比较器只给候选，不代表越权已在真实资产确认 |
| 三期 | `tests.test_defense`、`tests.test_upgrade_cli` | 项目内合成 JSONL 日志、资产/快照差异比较 | 归属门和隐私处理正确；不代表已执行生产防护改动 |

验证产物应保存在以下位置：

| 证据类型 | 位置 |
| --- | --- |
| 当前工具状态 | `validation/tools/` |
| 本地靶场验收与分数 | `validation/autotest/` |
| 业务 API / VAmPI 验证 | `validation/business-api/` |

升级前的三靶场测试分数只能作为历史基线，不能代表新增 VAmPI、真实补天目标或赏金成功率。每次升级后，应以新的 `validation/` 工件更新最终验收结论。

## 8. 已知的环境依赖与诚实状态

1. Windows 安全软件可能阻止 Nuclei 等安全工具的原生二进制。平台不绕过防护；应保持阻止状态，并使用已核验的回退运行方式或在合规测试环境中由管理员处理。
2. BBOT、testssl.sh 等项目在 Windows 上可能受到 Python/POSIX/系统工具依赖限制。工具状态页会显示实际状态，不能把“配置了包装器”视为“已成功运行”。
3. Docker Desktop 必须运行，四个靶场才会显示为 `READY`。容器镜像固定摘要并只发布到 `127.0.0.1`；Docker 不可用时，平台应提示依赖阻止。
4. 业务逻辑比较需要两个真实的、已授权的测试账号和明确测试对象。缺少这些条件时，系统不应猜测账号、枚举对象或生成漏洞结论。
5. 防护日志分析目前是项目内 JSONL 导入与统计分析；其他日志格式需要先在项目内转换为受控 JSONL，或经后续适配器支持。
6. 远程 AI 可用性、成本、模型名称和服务条款由提供商决定，必须在实际调用前以当前控制台状态和提供商页面为准。

## 9. 操作上的最终责任

使用者应在每个真实目标上完成以下人工工作：核对补天项目的允许范围与禁止项、保存授权依据、确认自动化是否允许、选择低影响步骤、复现候选、最小化影响、保护用户数据，并自行在补天平台提交报告。SRC-Auto 的价值在于把这些步骤变得更有条理、更可审计、更少误操作；它不能替代授权、专业判断或平台规则。

完整的逐步操作说明见 [三期平台完整使用手册](THREE_PHASE_USER_MANUAL.md)。
