# v0.14.1：任务专属动作目录、真实执行校验与验收

日期：2026-10-14（Asia/Shanghai）。本报告描述源码改动及本机实际验证；正式发行必须另通过 GitHub Actions、不可变标签和公开包校验，以 GitHub Releases 为准。

## 1. 完成的优化

- 复用现有 Agent 循环、审批、工具、预算、报告和持久化架构，没有引入新 Agent 框架或依赖。
- 以 `ActionSpec/ActionRegistry` 正向登记真实函数和批准对象；同一个登记表产生菜单与执行分派，取代全局动作集合的减项。固定靶场不会再继承本机应用的被动分析或专用业务验证动作。
- 本机路由只接受 route-NNN；业务对象只接受 object-NNN；固定配方及控制动作只接受 entry；候选复核只接受 candidate。注册动作存在不等于当前阶段可用。
- 已执行动作/对象组合从后续菜单移除；被动分析必须在批准路由全部采集后才能执行。菜单不提供 finish，直到程序判定该模式的必查证据完整；finish 仍须引用真实必需观察。
- 四字段 JSON 和脱敏证据协议不变。普通格式/选择错误最多修正一次（共享额度）；未知动作、外来对象/证据、附加禁止字段、重复动作、STOP、未知在途结果仍失败关闭，不自动重试工具。
- 提示按任务模式精简，并加入安全四字段示例；输入仍受 6000 字节上限限制，云端费用、取消、令牌和资源保护不变。
- 原有三个任务页加入可展开的“动作菜单与执行校验”，展示最近菜单、必查缺项、固定配方/模型来源、校验、执行器和真实观察；旧记录缺新字段时明确提示。没有新任务调度守护进程。
- 动作协议升级为 local-readonly-v5；v4 暂停检查点不可静默续跑，避免旧菜单污染新流程。已完成历史报告不删除。

## 2. 额外修复的实际故障

- 大量 TCP 连接时，Windows NetTCPIP 枚举造成停止助手超过原有 15 秒测试期限。改用系统 netstat 数字 PID 列表，并保留精确回环地址、端口、唯一 PID、项目身份、启动模块和命令行核验；拒绝模糊所有者，不强制停止任务。原测试恢复通过（约 2.6 秒）。
- Docker 未响应时，旧 WinForms 靶场窗口同步执行每个 20 秒的元数据查询。仅元数据探测改为 3 秒，并把超时/无法启动查询表示为不可用，不误报容器已删除。真实启动及扫描执行的时间上限没有削弱。
- 本机 Docker Desktop 原有 AF_UNIX 通信端点导致启动故障。从普通 Windows WMI 启动渠道恢复 Engine 29.8.0；仍有原 6 容器、11 镜像，持久化数据保持 D 盘位置。没有工厂重置、删卷、清理镜像或修改 VHD。此前隔离的临时目录可恢复，未删除。

## 4. 使用方式

1. 关闭空闲的旧控制台，重新通过桌面启动器或 `START_DASHBOARD.bat` 打开新版；本轮验证不强行关闭用户原有 4173/4174 会话。
2. 想用 DeepSeek 时在本次启动选择允许云端，再确认系统设置中的既有密钥状态；打开页面本身不会调用模型。无需重新输入已有 DPAPI 密钥。
3. 选择本地靶场，或在本机应用/业务页面录入精确范围、确认授权及时间窗，再人工启动任务。先等真实健康状态就绪，不把“启动容器”等同于“开始检测”。
4. 在任务详情展开“动作菜单与执行校验”；核对程序固定工作、模型建议、校验拒绝与实际结果。查看关联完整报告，最终复现、确认和补天提交仍由人工完成。
5. 升级后旧协议暂停任务需要重新创建；不自动续跑，不删历史任务，不绕过未确认范围。
