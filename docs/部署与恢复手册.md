# SRC-Auto 可视化控制台部署与恢复手册

## 适用范围

本手册对应代码优先的 React + Vite 可视化升级。所有项目代码、Node.js 专用运行时、依赖缓存、
日志和验证产物均应位于 `D:\网络安全文件夹\SRC-Auto` 或其子目录。它只描述本地控制台，
不会授予任何真实网站测试权限。

## 日常启动

在项目根目录打开 PowerShell：

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto'
.\tools\start_dashboard.ps1
```

启动器的行为是：

1. 检查 `dashboard`、项目专用 Node.js、Vite 依赖和 `dashboard\dist\index.html`；
2. 缺少构建产物时执行本地 `npm run build`，不自动安装依赖；
3. 以隐藏后台进程运行 Vite 预览，只绑定 `127.0.0.1`；
4. 轮询 `http://127.0.0.1:<端口>/`，就绪后打开默认浏览器；
5. 将标准输出和错误输出写到 `validation\dashboard\`，不写入密钥、会话或报告数据库。

常用参数：

```powershell
# 使用其他本地端口（范围 1024-65535）
.\tools\start_dashboard.ps1 -Port 4174

# 启动服务但不自动打开浏览器
.\tools\start_dashboard.ps1 -NoBrowser

# 前台运行，便于排查 Vite 错误；按 Ctrl+C 停止
.\tools\start_dashboard.ps1 -Foreground
```

统一启动器保留旧入口：

```powershell
.\START_SYSTEM.ps1 -Dashboard   # 新版浏览器控制台
.\START_SYSTEM.ps1 -LegacyGui   # 旧版 WinForms 主菜单
.\START_SYSTEM.ps1               # 兼容默认行为：旧版主菜单
.\START_SYSTEM.ps1 -RunLocalLab # 仅本地五靶场验收，不启动 Dashboard
```

Dashboard 入口只启动页面服务，不启动 Docker、五靶场、Ollama、DeepSeek、OpenRouter 或 OpenAI。
页面当前读取固定本地夹具；输入真实域名也不会产生网络接触。

## 停止服务

默认启动器会打印进程 ID。可在 PowerShell 中按 ID 停止该进程：

```powershell
Stop-Process -Id <启动器打印的进程ID>
```

如果忘记进程 ID，可先确认端口再停止占用该端口的 Node 进程；只操作本次启动的进程，不要
停止 Docker、Ollama 或其他用户进程：

```powershell
Get-NetTCPConnection -LocalPort 4173 -State Listen
```

前台模式直接按 `Ctrl+C`。停止 Dashboard 不会删除 `data`、`runs`、`reports`、`validation` 或
`config` 中的任何项目数据。

## 首次部署/依赖修复

项目专用 Node.js 位于：

`D:\网络安全文件夹\SRC-Auto\runtime\node-v22.23.0-win-x64\node.exe`

依赖清单和锁文件位于 `dashboard\package.json` 与 `dashboard\package-lock.json`。正常部署时
不要在系统目录安装 Node，不要把 `node_modules` 提交到 Git。若 `node_modules` 缺失，先在有
网络且符合组织策略的开发环境中完成依赖安装，再复制/缓存到 D 盘项目目录；日常启动器不会
静默联网安装。

离线构建/验收命令：

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto\dashboard'
npm test
npm run build
npm run build-storybook
npm run e2e -- --project=chromium
```

## 故障排查

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| “未找到项目专用 Node.js” | `runtime\node-v22.23.0-win-x64\node.exe` 是否存在 | 恢复同版本 D 盘运行时；不要改用来源不明的二进制 |
| “未找到 Vite 依赖” | `dashboard\node_modules\vite\bin\vite.js` 是否存在 | 在受控开发环境恢复锁定依赖；启动器不会自动下载 |
| “Dashboard 构建失败” | 查看 `validation\dashboard\dashboard.stderr.log` 和 `npm run build` 输出 | 先修复 TypeScript/依赖问题，构建失败时不会启动服务 |
| 端口已占用 | `Get-NetTCPConnection -LocalPort 4173` | 选择 `-Port 4174`，或只停止确认属于本次启动的进程 |
| 页面显示旧内容 | 检查 `dashboard\dist` 的构建时间，重新执行 `npm run build` | 刷新浏览器；不要删除项目运行期目录 |
| 中文乱码 | 使用 Windows Terminal/PowerShell，确认脚本 BOM | 保留 UTF-8/BOM；机器字段仍使用英文以兼容旧工件 |
| 事件或按钮无响应 | 执行 `npm test` 和 Playwright | 先看测试输出；不要把按钮绑定到绕过授权的脚本 |

## 验收与证据

升级验收记录在 `docs/validation/visual-upgrade-2026-08-26.md`。通过标准包括：Vitest、TypeScript/Vite
构建、Storybook 构建、Playwright 桌面/移动测试，浏览器控制台错误为 0，外部请求数为 0。
截图位于隔离工作树的 `validation\visual\`，运行产物不进入版本库。

完整 Python 回归仍在项目根目录执行：

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto'
python -m unittest discover -s tests -p 'test_*.py'
python -m compileall -q src_auto tools tests
```

若 Docker 不可用，本地靶场结果必须记录为依赖阻断，不能用历史分数替代当前轮证据。

## 安全回退

升级前快照：

- 提交：`cfd9d2d chore: capture pre-storybook visual baseline`；
- 标签：`baseline-pre-storybook-20260826`；
- 恢复说明：`docs/recovery/pre-storybook-rollback.md`；
- 恢复脚本：`tools/restore-pre-storybook-baseline.ps1`。

推荐在新工作树中回退，避免覆盖当前代码和运行期数据：

```powershell
Set-Location 'D:\网络安全文件夹\SRC-Auto'
.\tools\restore-pre-storybook-baseline.ps1 `
  -Destination 'D:\网络安全文件夹\SRC-Auto\.worktrees\rollback-pre-storybook-test'
```

脚本会拒绝已存在或不在项目目录下的目标路径，并从标签创建独立工作树。确认回退内容后，使用
`git worktree remove` 清理测试工作树；不要使用 `git reset --hard`，不要删除 `data`、`runs`、
`reports`、`validation` 或 `config`。

## 当前边界

本次升级只完成可视化纵向切片和本地夹具交互。FastAPI/SSE 实时后端、WebView2 桌面嵌入、
Burp/ZAP 编排、真实授权目标模拟和远程 AI 接入均需后续独立设计、授权和验收；前端构建成功
不等于这些能力已启用。
