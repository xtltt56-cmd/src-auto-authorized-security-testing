# SRC-Auto 代码优先可视化升级规格

## 文档状态

- 日期：2026-08-26
- 状态：用户已明确要求放弃 Figma 冻结并开始升级
- 项目根目录：`D:\网络安全文件夹\SRC-Auto`
- 产品定位：SRC-Auto 授权安全测试编排与候选漏洞研判平台
- 适用环境：Windows 10/11，本地浏览器或后续 WebView2 桌面壳

本规格是旧版 Figma 冻结条款的实现修订。已有 Figma 文件、PNG 参考稿和 WinForms 界面不删除；它们只作为视觉参考。新的页面以本规格、真实交互验收和本地截图对照为准，不依赖在线设计工具或外部 CDN。

## 1. 升级目标

把当前难以观察进程、按钮反馈不明确、文字容易截断的桌面控制台升级为一个清晰、中文优先、可真实操作的本地 Web 控制台。首个可交付版本聚焦一个完整纵向切片：

```text
选择本地靶场或保存授权草稿
        ↓
显示明确的安全边界和当前状态
        ↓
启动本地夹具任务并实时展示阶段、事件、计数和日志
        ↓
查看候选 Finding 与脱敏报告内容
        ↓
人工决定是否进入后续授权确认或补天提交
```

本期不把真实目标接入到自动化测试，也不把任何扫描告警自动认定为漏洞。

## 2. 安全与范围边界

必须满足：

1. 默认数据来自内置本地夹具，目标地址只使用 `127.0.0.1` 或 `localhost`；
2. 授权目标表单可以保存草稿，但保存、预览和校验不产生网络副作用；
3. 真实目标启动按钮在未完成人工授权、Scope、时间窗和方法确认时不可用；
4. 远程 AI 开关默认关闭，关闭时前端不请求任何远程地址；
5. 页面不加载 CDN、远程字体、外部 iframe 或第三方分析脚本；
6. 报告预览只读取项目根目录下的脱敏文本和 JSON，禁止执行 HTML/脚本；
7. 暂停、停止、重试和返回按钮均有可见状态反馈，不用静默的空处理器；
8. 任何失败都显示原因、下一步安全动作和是否可恢复，不提供绕过策略。

## 3. 视觉方向

### 3.1 色彩令牌

界面采用高对比深蓝导航 + 冷白工作区，保留现有 SRC-Auto 的识别度，同时降低大面积纯蓝造成的刺眼感：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--color-ink-950` | `#0B2239` | 左侧导航和深色状态条 |
| `--color-ink-800` | `#123B5D` | 主标题、深色边框 |
| `--color-ink-600` | `#47647B` | 正文和说明 |
| `--color-surface` | `#F7FAFC` | 页面背景 |
| `--color-panel` | `#FFFFFF` | 工作面、表格、抽屉 |
| `--color-border` | `#D6E0E8` | 分隔线、输入框边界 |
| `--color-primary` | `#0B84F3` | 主按钮、选中状态、进度 |
| `--color-primary-dark` | `#075EAE` | hover、焦点环、链接 |
| `--color-success` | `#168A55` | 完成、健康、已授权 |
| `--color-warning` | `#B26A00` | 等待人工、警告 |
| `--color-danger` | `#C43D4B` | 失败、阻止、停止 |
| `--color-muted` | `#718497` | 次要文字、未执行 |

颜色之外，所有状态必须同时呈现文字、图标和 `aria-label`。焦点环使用 `0 0 0 3px rgba(11,132,243,.28)`，不依赖颜色作为唯一信息。

### 3.2 排版与容器

- 字体优先使用系统中文无衬线字体：`"Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans SC", sans-serif`；
- 基础字号 15px，正文行高 1.6，按钮/输入字号 14px，标题使用 28/22/18px 三级；
- 主内容最大宽度 1440px，页面左右内边距 28px（小屏 16px）；
- 左侧导航宽度 232px，窄屏折叠成顶部菜单；
- 面板圆角 12px，按钮圆角 8px，输入框圆角 8px；
- 阴影只用于浮层和状态卡，不对每一块内容重复加阴影；
- 最小支持窗口 1180×720，1366×768 和 1920×1080 为验收尺寸；
- 所有可点击区域最小 40×40px，表格和日志可滚动但不让页面水平溢出。

### 3.3 动效

仅使用 160–220ms 的透明度、背景和位置过渡，表示导航切换、阶段完成和抽屉展开。`prefers-reduced-motion: reduce` 时关闭过渡和旋转动画。

## 4. 信息架构与页面

### 4.1 总览工作台

首屏提供三个清晰入口：

1. **本地靶场检测**：默认推荐，显示五个本地靶场健康状态和“只访问回环地址”说明；
2. **新建授权目标**：打开目标录入表单，只能保存草稿并进入授权确认；
3. **离线审阅**：选择项目目录内的源代码或报告，显示文件解析进度，不产生网络请求。

首屏还显示当前任务、最近事件、候选数量、阻止数量和报告数量。没有任务时显示下一步操作，而不是空白卡片。

### 4.2 新建授权目标

表单字段：项目名称、目标 URL、允许主机、允许端口、排除路径、授权起止时间、允许方法、并发上限、请求上限、授权证明备注。每个字段有简短中文帮助文字。保存草稿后展示：

- 目标标准化结果；
- Scope 哈希后缀（只显示后 8 位）；
- 将要阻止的高风险动作清单；
- “仅保存草稿”按钮；
- “进入人工确认”按钮；
- 明确的“保存草稿不会访问目标”提示。

### 4.3 任务实时详情

采用三列布局：

- 左列 240px：阶段轨道，从策略检查到报告生成，当前阶段高亮；
- 中列弹性区域：事件时间线和实时日志，支持等级、阶段、工具筛选；
- 右列 260px：入口、API、候选、阻止、错误计数以及目标/授权摘要；
- 底部固定操作条：暂停、停止、打开报告、导出脱敏事件；
- 顶部显示任务名称、模式、耗时、心跳和安全状态。

### 4.4 靶场矩阵

五个靶场用表格/列表而不是重复大卡片展示：Juice Shop、DVWA、WebGoat、VAmPI、Business API。每行显示健康、阶段、耗时、候选和报告入口；点击行展开该靶场事件。

### 4.5 Finding 与报告

左侧候选列表显示标题、严重度、来源和状态；右侧显示脱敏证据、重现前提、影响、独立裁决和人工操作按钮。报告文件树中的文件名必须可以点击，内容通过只读预览加载并显示文件路径和大小。

### 4.6 任务历史与设置

历史页按运行状态筛选 `已完成`、`已暂停`、`已阻止`、`失败`，支持在新窗口/新页查看，不修改旧任务。设置页显示本地模型、远程 AI（默认关闭）、密钥已配置/未配置（不显示值）、工具状态和 D 盘存储路径。

## 5. 组件清单

核心组件统一放在 `dashboard/src/components`：

- `AppShell`：侧栏、顶部栏、页面容器和全局消息；
- `StatusBadge`：`running`、`waiting`、`blocked`、`failed`、`completed`、`idle`；
- `ProgressBar`：带数值文本、动画和 `aria-valuenow`；
- `MetricStrip`：四个关键计数；
- `StageRail`：阶段、时间、状态和错误说明；
- `EventTimeline`：时间线、等级筛选和事件详情；
- `TargetForm`：授权目标草稿输入和校验；
- `LabMatrix`：五靶场列表与行级详情；
- `FindingList` / `FindingDetail`：候选研判；
- `ReportViewer`：安全文件预览；
- `ActionBar`：暂停/停止/打开报告/导出事件。

每个组件必须有正常、焦点、禁用、等待、错误或空数据状态的 Storybook story；按钮使用原生 `button`，不使用仅绑定 `div` 点击事件。

## 6. 数据与状态

前端类型位于 `dashboard/src/lib/types.ts`。最小模型如下：

```ts
type TaskState = 'idle' | 'queued' | 'running' | 'paused' | 'blocked' | 'failed' | 'completed';
type TaskKind = 'local-lab' | 'offline-review' | 'authorized-draft';

type TaskSummary = {
  id: string;
  name: string;
  kind: TaskKind;
  state: TaskState;
  stage: string;
  progress: number;
  elapsedSeconds: number;
  counters: { endpoints: number; api: number; candidates: number; blocked: number; errors: number };
  networkContact: 'none' | 'loopback' | 'authorized-target';
  updatedAt: string;
};

type TaskEvent = {
  id: number;
  taskId: string;
  time: string;
  level: 'info' | 'success' | 'warning' | 'danger';
  stage: string;
  message: string;
  tool?: string;
  redacted: true;
};
```

默认数据由 `dashboard/src/lib/fixtures.ts` 提供，明确标记为 `source: 'local-fixture'`。未来接入回环 API 时只替换 `taskRepository`，不改变组件的状态模型。远程请求适配器必须默认返回“禁用”，不能在 fixture 模式下尝试连接网络。

## 7. 交互验收

必须通过以下真实浏览器路径：

1. 点击侧栏“本地靶场”，页面切换且选中状态变化；
2. 点击“启动本地检测”，按钮变为“运行中”，阶段轨道和事件日志逐步更新；
3. 点击“暂停”，状态变为“已暂停”，再点击“继续”恢复；
4. 点击“停止”，状态变为“已停止/已取消”，不再追加模拟事件；
5. 点击候选 Finding，右侧内容更新；
6. 点击报告文件名，显示文件内容和脱敏提示；
7. 打开“新建授权目标”，空字段显示中文校验，填写后仅保存草稿；
8. 关闭并重新打开任务详情，fixture 状态恢复且没有未处理控制台错误；
9. 在键盘 Tab 顺序下所有按钮、表单、筛选和报告链接可到达；
10. 1366×768、1920×1080、390×844 三种尺寸下无主内容裁切和水平滚动。

## 8. 测试与门禁

- Vitest：类型/状态派生、表单校验、事件追加、报告路径安全；
- Storybook：组件状态和可访问名称；
- Playwright：页面导航、暂停/停止、报告查看、授权草稿和响应式；
- 浏览器控制台：未处理错误数为 0，第三方请求数为 0；
- Python 现有 239 个单元测试作为后端回归基线；
- 每次门禁生成 `docs/validation/visual-upgrade-<date>.md`，记录命令、通过数、截图尺寸和已修复偏差；
- 所有临时截图和浏览器追踪文件放在 D 盘 `validation/visual/`，不提交密钥和运行期数据库。

## 9. 兼容和回退

新前端先以独立 `dashboard/` 运行，不接管旧快捷方式。验证通过后，启动器增加 `-Dashboard` 选项；默认入口仍可通过 `-LegacyGui` 启动原 WinForms。升级失败时使用 `tools/restore-pre-storybook-baseline.ps1` 创建基线工作树，运行期数据不被删除。

## 10. 完成定义

本轮代码优先可视化升级只有在以下条件同时满足时才算完成：

1. Dashboard 可以在本地启动，首页和主要页面没有乱码或截断；
2. 所有主要按钮有真实状态变化，错误路径可见且可恢复；
3. 本地靶场任务从创建到完成的阶段、事件、计数和报告可查看；
4. 授权草稿保存不访问网络，人工确认仍是后续动作的前置条件；
5. Storybook、Vitest、Playwright 和现有 Python 回归均通过；
6. 新界面未替换旧启动器，基线标签和回退脚本可用；
7. 页面实现只访问本地 fixture 或回环服务，外部目标接触数为 0。
