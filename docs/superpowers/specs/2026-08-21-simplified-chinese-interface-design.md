# SRC-Auto 简体中文界面与说明设计

日期：2026-08-21
项目：`D:\网络安全文件夹\SRC-Auto`
方案：A——中文优先的人机界面，保留稳定英文机器字段

## 1. 目标与范围

将当前操作入口和说明尽可能本地化为简体中文，降低首次使用和人工复核的理解成本，
同时不破坏已有脚本、JSON 工件、测试和审计查询。

本次覆盖：

1. `START_SYSTEM.ps1` 桌面一键启动窗口的提示、步骤、失败建议和结束提示；
2. `juice-shop-status`、`juice-shop-baseline`、`juice-shop-zap` 的终端摘要；
3. CLI 帮助文本、阻断原因和安全提示；
4. 机器可读 JSON 增加 `*_zh` 中文说明字段，但保留现有英文键和值；
5. README、USER_MANUAL、验证报告和已知问题中的操作说明；
6. 为中文文本、机器字段兼容性和安全门控增加测试。

本次不做：

- 不增加 Web 控制台、账号系统或新的监听端口；
- 不改变目标白名单、Scope、网络联系、AI 路由或自动提交策略；
- 不把英文机器字段重命名为中文；
- 不翻译第三方工具原始 stdout/stderr，原始输出继续按审计工件保存；
- 不扩大真实目标扫描权限。

## 2. 用户界面约定

### 2.1 终端文本

面向操作者的固定文本使用简体中文，包含：

- 操作阶段，例如“检查 Docker Desktop”“执行本地发现基线”；
- 结果，例如“可访问”“未运行”“被安全范围阻止”；
- 下一步建议，例如“请确认容器仅绑定 127.0.0.1:3000”；
- 安全警告，例如“POSSIBLE 不等于已确认漏洞”。

### 2.2 机器字段

所有已有英文 `status`、`reason`、`network_contact`、`finding_count` 等字段和枚举值
保持不变，以兼容现有脚本与历史工件。需要解释的输出增加对应字段：

```json
{
  "status": "COMPLETED_DISCOVERY_ONLY",
  "status_zh": "已完成发现，尚未执行漏洞扫描",
  "reason": "vulnerability_scanners_not_run",
  "reason_zh": "本次只执行发现，未运行漏洞扫描器"
}
```

中文字段使用 `_zh` 后缀，不覆盖原始工具名称、URL、路径、模型名、SHA-256 或英文枚举。

### 2.3 语言控制

默认输出为简体中文。为保留自动化和故障排查能力，增加可选环境变量：

```powershell
$env:SRC_AUTO_LANG = "zh-CN"
```

`zh-CN` 是默认值；未来可以预留 `en-US`，但本次不实现完整英文翻译。JSON 输出始终
保持机器字段兼容，并在适用时带中文说明字段。

## 3. 组件设计

### 3.1 本地化模块

新增轻量模块 `src_auto/i18n.py`，只负责固定状态码、原因和阶段的中文映射，以及
终端摘要格式化。映射缺失时回退到原始英文值，不能因为翻译缺失阻断安全流程。

接口保持小而明确：

- `status_zh(value)`：返回状态中文说明；
- `reason_zh(value)`：返回原因中文说明；
- `message(key, **values)`：返回固定操作文本；
- `with_zh_fields(document)`：为 JSON 文档补充适用的 `_zh` 字段。

### 3.2 CLI

CLI 在现有命令逻辑外增加中文摘要，不改变退出码。状态命令和阻断命令同时输出：

- 中文摘要供人阅读；
- 原有 JSON 工件路径和英文状态字段供脚本读取。

为了避免管道破坏，保留 `--json` 机器输出模式；默认交互输出使用中文。现有调用若
依赖纯 JSON，应继续显式传 `--json` 或读取工件文件。

### 3.3 一键启动器

`START_SYSTEM.ps1` 的阶段提示、失败信息和下一步建议改为简体中文。Docker 命令、
目标 URL、路径和模型名保持原样。脚本仍然只启动本地回环靶场，不启动真实目标流程。

### 3.4 文档

README 和 USER_MANUAL 以“功能—准备—操作—输出—限制—故障处理”顺序组织；验证报告
保留历史快照，但在文档顶部明确当前事实源。新增中文字段说明、常用命令表和安全边界
说明。

## 4. 错误处理与安全约束

- 翻译映射缺失只回退文本，不改变安全决策；
- 外部目标、错误端口、越界重定向、输出目录越界仍由原有策略拒绝；
- JSON 中的 URL、路径、Key 环境变量名、模型名和摘要不翻译、不截断；
- 不在中文摘要中打印 Cookie、Token、密码或 API Key；
- 原始第三方工具输出只保留现有脱敏和长度上限；
- `POSSIBLE`、`NOT_RUN`、`BLOCKED_*` 等状态必须明确解释，不能渲染成成功或漏洞确认；
- DeepSeek 和 OpenAI 仍是人工启用，中文化不改变远程调用门控。

## 5. 测试策略

采用测试先行：

1. 增加状态、原因和阶段中文映射测试；
2. 增加 CLI 摘要和 JSON `_zh` 字段测试；
3. 增加未知状态回退测试；
4. 增加启动器中文关键提示和 loopback 绑定安全契约测试；
5. 运行全量单元测试、编译检查、JSON 工件解析和 `git diff --check`；
6. 手工运行 status/baseline/ZAP，确认输出可读且安全字段不变。

验收标准：

- 默认人机提示为简体中文；
- 现有英文状态字段和退出码不变；
- 70 项既有测试与新增测试全部通过；
- 本地目标仍严格为 `127.0.0.1:3000`；
- 远程 AI 调用仍为 0，除非人工明确启用；
- 文档和新增文件均位于项目 D 盘目录。

## 6. 兼容性与回滚

现有工件不重写历史字段；新运行会增加中文说明字段。若终端编码不支持中文，固定
文本允许显示替代字符，但 JSON 使用 UTF-8 写入；机器字段不受影响。回滚时删除本地化
模块引用并恢复启动器/文档文本即可，不需要删除 Docker 数据或验证工件。
